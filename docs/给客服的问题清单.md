## 🔴 P0 安全 —— 不问清楚不敢上电

### Q1. 三个硬件保护默认全是关的，这是有意的吗？

`robot_param/motor_param/6dof_Panthera_params_follower.yaml`：

```yaml
motor_timeout_ms: 0        # 注释说"设为0表示禁用超时功能"
pos_limit_enable: false    # 每个电机都是 false
tor_limit_enable: false    # 每个电机都是 false
```

**问**：
1. 出厂建议值分别是多少？
2. `motor_timeout_ms` 触发后进入的"**阻尼模式**"具体是什么行为？阻尼系数多大？
   手臂会缓慢下垂还是基本保持？
3. 做力矩控制时，你们建议开还是关？

> **为什么问**：我们要跑 Python 力矩环。Python 有 GC 停顿、页错误、被抢 CPU 的风险。
> 如果 `motor_timeout_ms: 0`（禁用），控制循环一旦卡住，**电机会保持上一条力矩指令继续加速**。
> 这是力矩控制最危险的失效模式。我们已在软件层写了看门狗，但**硬件层的兜底更可靠**。

### Q2. `tor_upper: 5 / tor_lower: -3` 是占位值吗？

配置里 **7 个电机（含夹爪）的这两个数完全一样**，且不对称：

```yaml
tor_upper: 5
tor_lower: -3
```

**问**：
1. 这是出厂占位值还是有实际含义？
2. 单位是什么——**电机端**力矩还是**关节端**（减速后）力矩？
3. 为什么正负不对称（+5 / −3）？
4. J1（关节端堵转 21 N·m）和夹爪用同一个数，合理吗？

> **为什么问**：这决定了"电机自己会不会限力矩"。如果启用且单位是关节端，
> 5 N·m 会把 J2/J3（额定 10 N·m）限死；如果是电机端，×36 后又太大。
> 数值含义不清就不敢启用。

### Q3. 力矩控制示例里 `set_stop()` 全被注释掉了，退出时手臂会掉吗？

- `2_gravity_compensation_control.py` 等**所有力矩控制示例**里，
  `except KeyboardInterrupt` 分支的 `robot.set_stop()` 都是**注释状态**（共 13 处）
- 而 `1_forward_kinematics_test.py` 这类位置控制示例里是**启用**的
- 同时配置里 `exit_motor_brake_flag: true`，注释写"系统退出时电机自动释放刹车，允许自由运动"

**问**：
1. 力矩模式下 Ctrl+C / 程序崩溃，手臂会**直接自由落下**吗？
2. `set_stop()` 是断使能还是把力矩置零？它在 `Panthera.py` 里没有定义，
   是在 `hightorque_robot` 预编译包里吗？
3. 关节有**抱闸**吗？断电瞬间靠什么托住手臂？
4. 有没有**硬件急停**接口？推荐怎么接？
5. 力矩模式下推荐的安全退出流程是什么？

> **为什么问**：这是我们上电前必须演练的第一件事。
> 我们的计划是"手放急停旁边"——但得先知道急停是什么。


### Q4. 底座怎么固定？全速运动时的反力矩多大？

**问**：
1. 官方推荐的固定方式是什么？（桌面夹具 / 螺栓 / 配重底板？）
2. 手臂在**最大加速度**（`acceleration_limits: 2.0 rad/s²`）下伸直运动时，
   底座承受的**倾覆力矩**大约多少 N·m？
3. 自重 4.35 kg、臂展 860 mm，只靠自重放桌上够吗？还是必须夹紧/打螺栓？
4. 底座安装孔位图有吗？（`Panthera-HT_Model` 仓库里有吗）

> **为什么问**：这是**开箱第一件事**，而且做错了很危险——
> 底座松动时手臂一动整台就晃，不仅数据全废（辨识假设基座固定），
> 还可能直接把机器甩到地上。
> 我们要跑的激励轨迹是**六个关节同时高频运动**，比一般演示激烈得多。

### Q5. 力矩控制 / RL 实验的保修边界在哪？

我们要做的是**高风险操作**：纯力矩控制、参数辨识（六轴同时高频激励）、
强化学习策略部署（早期策略输出可能很激进）。

**问**：
1. 哪些操作会导致**保修失效**？纯力矩模式在保修范围内吗？
2. 最常见的**损坏模式**是什么？（减速器？电机？编码器？线束？）
3. 有**备件**卖吗？（单个关节模组、线束、夹爪）大概价格和周期？
4. 有没有一份"这样做会损坏机器"的明确清单？

> **为什么问**：与其撞坏了再问，不如先知道边界在哪。
> 如果某些操作有风险，我们愿意在软件层加保护——但得先知道是哪些。

## 🟠 P1 决定控制器设计 —— 问清楚能省几天调试

### Q6. 整臂力矩环实际能跑多少 Hz？一个往返多少 ms？

我们查到的：
- 拓扑：**7 个电机共用 1 个 `/dev/ttyACM`**，`Seial_baudrate: 4000000`（4 Mbps）
- 官方示例的控制率从 **100 Hz 到 500 Hz 都有**：
  - `2_gravity_compensation_control.py`：`sleep(0.002)` = 500 Hz
  - `2_gravity_friction_compensation_control.py`：`sleep(0.005)` = 200 Hz
  - `7_gamepad_cartesian_vel_control.py`：`control_period = 0.01` = 100 Hz，
    而且用了**绝对截止时间调度**并处理超时（`max_control_dt = 0.03`）

**问**：
1. `send_get_motor_state_cmd()` + `pos_vel_tqe_kp_kd()` 一个完整往返，**实测**多少 ms？
2. 整臂闭环力矩控制，你们**实测**能稳定跑到多少 Hz？
3. 抖动（jitter）有多大？最坏情况单周期能到多少 ms？
4. `7_gamepad` 里那个 `max_control_dt = 0.03`（30 ms）是遇到过实际问题才加的吗？

> **为什么问**：我们**实测**过延迟敏感度，有个悬崖：
>
> | 通信延迟 | CTC wn=100 的 RMS | 力矩饱和 |
> |---|---|---|
> | 4 ms | 0.00046 | 0% |
> | **6 ms** | **0.00719（涨 15 倍）** | **37%** |
>
> 低带宽（wn=30）则表现为力矩峰值悄悄涨 52%（11.99→18.26 N·m）而 RMS 不变——
> 余量被吃掉却看不出来。
> **知道真实延迟，我们就能直接算出可用带宽，不用上真机试错。**


### Q7. ⚠️ 力矩控制时 `get_current_pos()` 拿到的是**当前**状态还是**上一周期**的？

我们统计了全部示例脚本：

| 示例类别 | 是否调用 `send_get_motor_state_cmd()` |
|---|---|
| 力矩控制（`2_*`、`3_*`、`4_*`） | **一个都没有** |
| 遥操作 / 运动学（`0_*`、`1_*`、`5_*`、`7_*`） | **全部都有** |

而 `0_robot_set_zero.py` 里的注释写"**利用运控模式发送控制帧以读取电机反馈状态**"。

**问**：
1. `pos_vel_tqe_kp_kd()` 内部的 `motor_send_cmd()` 会**顺带触发状态回传**吗？
2. 如果会，那么下一次 `get_current_pos()` 拿到的是**这一帧指令之后**的状态，
   等于反馈里天然有 **1 个控制周期的延迟**——对吗？
3. 力矩控制循环里到底**要不要**显式调用 `send_get_motor_state_cmd()`？
   调用了会不会变成每周期两次往返、把控制率砍半？
4. 有没有"发指令的同时拿回状态"的单次往返接口？

> **为什么问**：这是**闭环反馈的正确性问题**，不是性能问题。
> 如果力矩环喂进去的是上一周期的 $q,\dot q$，那就等于凭空多了一拍延迟。
> 结合上一条 Q4 的延迟悬崖（4 ms 正常 / 6 ms RMS 涨 15 倍），**一拍就可能是决定性的**。
> 我们必须知道真实的反馈时序才能正确建模。

### Q8. `get_current_torque()` 的力矩是怎么来的？精度多少？

**问**：
1. 是**电流估算**（$\tau = k_t \cdot I \cdot n_{gear}$）还是有力矩传感器？
2. 出厂**标定过**吗？标称精度/线性度是多少？
3. 有温漂吗？连续跑 30 分钟会漂多少？
4. 摩擦、减速器效率算在里面了吗？

> **为什么问**：**参数辨识的输入就是这个力矩**。
> 我们的辨识流程要求测量噪声可控——已经验证过噪声 0.02 N·m 时参数误差 0.7%，
> 但如果实际是 0.5 N·m 或有系统性偏置，整套辨识方案要重新设计。
> 这是**决定辨识做不做得成**的问题。

### Q9. 力矩限幅到底该用哪一套？

官方示例里出现了**三套互相矛盾**的值（我们统计过全部脚本）：

| 值 | 出现次数 | 我们的理解 |
|---|---|---|
| `[10, 20, 20, 10, 5, 5]` | 2 处 | ？ |
| `[15, 30, 30, 15, 5, 5]` | 8 处 | ？ |
| `[21, 36, 36, 21, 10, 10]` | 2 处，与 `Follower.yaml` 的 `max_torque` 一致 | 堵转扭矩 |

**问**：
1. 这三套分别是什么含义？（额定 / 峰值 / 堵转 / 短时允许？）
2. **连续运行**（比如跑 10 分钟辨识轨迹）安全的持续力矩是多少？
3. 峰值力矩允许持续多久？有热保护吗？触发后什么表现？

> **为什么问**：我们现在保守取了最小的一套。但如果它其实是"额定"，
> 我们就白白浪费了一半控制权限；如果连续运行限值更低，我们的辨识轨迹可能烧电机。

## 🔵 P1.5 RL 与 sim2real —— 我们项目的主线

> **背景**：我们计划做「系统辨识 + 传统控制」与「域随机化 + 强化学习」的定量对照实验，
> 路线是 **IsaacLab 训练 → MuJoCo 做 sim2sim 交叉验证 → 真机部署**。

### Q10. 官方有没有做过 RL（不是模仿学习）？

我们查到 `Panthera-HT_RoboTwin` 是基于 **RoboTwin 2.0 + SAPIEN**，
面向 **ACT / Pi0 / RDT / DP / DP3 等模仿学习（VLA）**，
而且 README 第 355 行明确写：

> 「本仓库不包含 Panthera 真机 SDK、真机控制或 **sim-to-real 安全保证**。」

**问**：
1. 有没有**强化学习**（PPO/SAC 这类）的官方或社区工作？
2. 有没有 **IsaacLab / Isaac Gym / MuJoCo** 的官方环境？还是只有 SAPIEN？
3. 有没有 **USD** 格式的模型？还是要我们自己从 URDF 转？
4. RoboTwin 采的专家数据训出来的策略，**有人成功部署到真机过吗**？
   成功率大概什么水平？
5. `Panthera_digital_twin` 用的是什么物理引擎？和 RoboTwin 什么关系？

> **为什么问**：如果官方从没做过 sim2real，我们就是**第一个**——
> 那我们要自己承担全部风险，也更需要前面那些底层参数（延迟、力矩精度、转子惯量）。
> 这直接决定我们的时间预算。

### Q11. RL 策略部署：跑在上位机还是板卡？

**问**：
1. 推荐把策略（ONNX，约 2~3 层 MLP，50~100 Hz）跑在**板卡**上还是**上位机**上？
2. 如果跑板卡：板卡能直接调 `hightorque_robot` 吗？
   （`motor_whl/` 里有 `aarch64` 的 wheel，是给板卡准备的吗？）
3. 如果跑上位机：USB 那一段的延迟和抖动会不会成为瓶颈？
4. 有没有人做过**脱机运行**（不接电脑，上电即跑）？

### Q12. RL 策略用 MIT 模式时，kp/kd 取多少？

RL 策略的标准做法是**输出关节位置目标**，由电机内部的 PD（MIT 模式的 kp/kd）执行：

$$\tau = k_p(q_{des}-q) + k_d(\dot q_{des}-\dot q) + \tau_{ff}$$

**问**：
1. `pos_vel_tqe_kp_kd()` 里 kp/kd 的**单位**是什么？（N·m/rad？还是电机内部的无量纲标度？）
2. kp/kd 的**取值范围**是多少？超过多少会不稳定？
3. 各关节推荐的 kp/kd 是多少？（我们知道电机内部以 3 kHz 执行，
   所以能比外层 Python 环用高得多的增益）
4. 电机内部 PD 是**纯 PD** 还是带积分/前馈/滤波？有没有内部限幅？

> **为什么问**：这是 RL 部署链路里**最关键的一组数**。
> 训练时仿真里的 PD 增益必须和真机电机内部的 PD **完全对齐**，
> 否则策略学到的是另一台机器。而单位不明就没法对齐。

### Q13. 零位可重复性：断电重启后还是同一个零位吗？

**问**：
1. 编码器是**单圈**还是**多圈**？断电后位置记忆保持吗？
2. `0_robot_set_zero.py` 设的零位是**写进电机 flash** 还是只在本次会话有效？
3. 断电重启后，同一个物理姿态读出来的关节角**重复性**是多少？（±多少 rad）
4. 有没有机械式的零位标定工装 / 限位块？

> **为什么问**：⭐ **零位漂移是 sim2real 的隐形杀手**。
> 策略是在"关节角 = 某个数"的世界里训练的。如果真机今天的零位和昨天差 0.05 rad，
> 策略看到的观测就是系统性偏移的，表现会莫名其妙地变差，而且**很难 debug**——
> 因为看起来一切正常。
> 知道重复性，我们才能决定：是每次开机重新标定，还是把它当成域随机化的一项。

### Q14. 域随机化该随机化哪些参数、范围多大？

我们发现**官方仿真资产里没有任何动力学参数**：

- `RoboTwin/assets/embodiments/panthera-6dof/panthera_6dof.urdf`
  的 `<dynamics>` 标签数量 = **0**（无 damping、无 friction）
- 其 link2 惯量 `izz="0.02272105"` 与 SDK 版 URDF **逐位相同**
  → 说明两边用的都是**同一份纯 CAD 惯量**，都没有辨识过

**问**（这些是域随机化范围的依据）：
1. **个体差异**：同型号不同机器之间，摩擦、力矩常数、背隙的离散度大概多少？
2. **温漂**：连续运行 30 分钟后，摩擦和力矩输出会变化多少？
3. **磨合**：新机器和跑过 100 小时的机器，摩擦差多少？
4. **负载**：装上夹爪（和后续的相机）后，末端的质量/惯量参数你们有数据吗？

> **为什么问**：域随机化的核心是"**范围要覆盖真机，但不能太宽**"——
> 太窄会 sim2real 失败，太宽会让策略过度保守、性能下降。
> 这些离散度数据是定范围的唯一依据。没有的话我们只能自己辨识 + 拍脑袋加余量。

### Q15. RL 策略输出可能很"抖"，硬件层有什么保护？

RL 策略在训练早期或遇到分布外状态时，输出可能剧烈跳变。

**问**：
1. 电机固件里有没有**指令变化率限制**（jerk / 力矩斜率限制）？
2. 连续下发相邻两帧差异很大的位置目标，电机会怎么反应？
3. 有没有推荐的"策略输出 → 电机指令"之间的**滤波/限幅**做法？
4. 长时间在高力矩下运行（RL 策略可能不像人写的控制器那样"温柔"），
   过热保护什么时候触发？触发后是降额还是直接断使能？

### Q16. 观测里能拿到哪些量？延迟分别是多少？

RL 的观测通常是 $[q, \dot q, \tau, q_{des}^{prev}, \ldots]$。

**问**：
1. `get_current_pos/vel/torque` 三个量的**时间戳是同一时刻**的吗？
2. 速度是**直接测**的还是由位置**差分**得到的？如果是差分，用了什么滤波？
   （滤波会引入相位滞后，训练时必须建模）
3. 有没有 IMU 或其他额外传感器可用？
4. 夹爪的位置/力反馈能读吗？延迟和关节一样吗？

> **为什么问**：观测的延迟和滤波特性**必须在仿真里复现**，
> 否则策略在真机上看到的观测和训练时不是一个东西。
> 「速度是不是差分出来的」尤其重要——差分速度的噪声和相位特性和真实速度差很远。

## 🟣 P1.6 夹爪 —— 阶段 2「状态型抓取」的核心硬件

> 我们的路线是 **阶段1 轨迹跟踪（只要臂）→ 阶段2 状态型抓取（＋夹爪）→ 阶段3 视觉抓取（＋D405）**。
> 阶段 2 的 RL 动作空间里有**一维是夹爪**，奖励函数要用到**夹持力**。

我们从 SDK 查到的：

```python
gripper_control(pos, vel, max_tqu=0.5)          # 默认最大力矩 0.5 N·m
gripper_control_MIT(pos, vel, tqe, kp, kd)      # 支持 MIT 五参数模式
gripper_open(pos=1.6)  /  gripper_close(pos=0.0)
```
配置：`gripper_limits: 0.0 ~ 2.0`，电机型号 `3536_32`（减速比 32）。

### Q17. 夹爪的力学指标是多少？

**问**：
1. **最大夹持力**是多少牛（N）？`max_tqu=0.5` N·m 对应指尖多大的力？
2. 行程 0~2.0 是什么单位（rad？），对应**指间开口**多少 mm？
3. 是**平行夹爪**还是连杆式？指尖轨迹是直线还是弧线？
4. 夹爪 + 法兰装上之后，**末端增加的质量和惯量**是多少？
   （我们要把它加进动力学模型，否则 J5/J6 的辨识和控制都会偏）

### Q18. 夹爪能做**力控**吗？力反馈准不准？

**问**：
1. `gripper_control_MIT` 的 `tqe` 能做**恒力夹持**吗？还是只能限幅？
2. `get_current_torque_gripper()` 读出的力矩，能换算成**指尖夹持力**吗？换算系数是多少？
3. 这个力反馈标定过吗？精度大概多少？
4. 抓一个易碎物体（比如纸杯）时，推荐怎么控？

## 🟡 P2 模型精度 —— 决定辨识工作量

### Q21. URDF 的 `<inertia>` 含转子惯量吗？

**问**：
1. URDF 里的惯量是**纯 CAD 几何导出**，还是含了电机转子的反射惯量？
2. 能提供**转子惯量 $J_m$** 吗？（每个型号：5047 / 6056 / 4438）

> **为什么问**：减速比 36 ⇒ 反射惯量 = $J_m \times 36^2$。
> 按典型 $J_m \approx 10^{-5}$ 估算得 0.013 kg·m²，
> 而 URDF 里 link2 的 $I_{zz}$ 只有 **0.0227** —— **反射惯量占 57%**。
> 这个量级 CAD 导不出来。如果 URDF 没含，我们的模型系统性偏小一半，
> CTC 和 RL 的 sim2real gap 会非常大。**这是最影响仿真保真度的一个数。**

### Q22. 示例里的摩擦系数是辨识值还是经验值？


但注释写"**需要根据实际机器人进行辨识和调整**"。

**问**：
1. 这组数是**某台样机的实测值**，还是拍的经验值？
2. 不同个体差异有多大？
3. 出厂有**逐台标定数据**随机器附带吗？
4. 有没有官方推荐的辨识流程 / 脚本？

### Q23. 能读**电机温度**吗？能**单独使能/去使能**某个关节吗？

我们在 `Panthera.py` 里**没有找到**温度读取或单关节使能的接口。

**问**：
1. 有没有读电机温度的接口？（在 `hightorque_robot` 预编译包里吗？）
2. 能不能**单独去使能**某一个关节，让它自由转动而其他关节保持不动？
3. 电机温度到多少会触发降额/保护？触发后是什么表现？

> **为什么问**（两条都直接影响辨识方案的**有效性**）：
>
> **① 温度**：摩擦系数**强烈依赖温度**。我们的激励轨迹要连续跑 10 分钟以上，
> 期间如果摩擦漂移了，辨识出来的就是一个"平均意义上谁也不是"的值。
> ⭐ 能读温度，我们就能把它当协变量记录、甚至辨识出温度依赖；
> 读不到就只能靠"每次先热机 X 分钟"这种土办法，而且**无法验证它到底有没有用**。
>
> **② 单关节使能**：辨识的常见做法是固定其他关节、单独激励一个，
> 能大幅改善条件数。做不到就只能整臂同时激励。

### Q24. 能提供电机电气参数吗？

**问**：力矩常数 $k_t$、相电阻 $R$、减速器**效率**、**背隙**（arcmin）。

> **为什么问**：$k_t$ 和 $R$ 做前馈补偿和能耗分析要用；
> 效率影响"指令力矩 → 实际输出力矩"的换算；背隙决定位置精度上限和 RL 的随机化范围。
