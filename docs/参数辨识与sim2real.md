# 参数辨识与 sim2real

> 这一篇讲**这个项目最值钱的那条链**：
> 官方模型缺什么 → 怎么用真机把它测出来 → 怎么证明补上之后真的变好了。
>
> ⚠️ 前置知识见 armctrl 讲义 **14 篇 §八/§九**（回归矩阵、基参数、激励轨迹）
> 和 **15 篇 §三/§五**（状态空间、采样与离散化）。

---

## 一、问题：官方模型缺了「传动系统」这一层

高擎官方 URDF 是 CAD 导出的。**连杆几何和连杆惯量可信**，但下面三样缺失：

| 缺什么 | 量级估计 | 为什么 CAD 给不出 |
|---|---|---|
| **转子反射惯量** | $J_{rotor}\cdot N^2$，$N{=}36$ ⇒ **×1296** | 传动系统属性，不是连杆几何 |
| **库仑摩擦** $F_c$ | 0.04–0.2 N·m（官方建议值） | 几何模型里不存在摩擦 |
| **粘滞摩擦** $F_v$ | 0.02–0.06 N·m·s/rad | 同上 |

**转子惯量到底有多重要**——拿真数字比一比：

$$J_{\text{反射}} = 10^{-5} \times 36^2 = 0.013\ \mathrm{kg\cdot m^2}
\qquad\text{而}\qquad
I_{zz}^{\text{link2}} = 0.0227\ \mathrm{kg\cdot m^2}$$

⭐ **反射惯量是连杆惯量的 57%**。忽略它，仿真里的臂会比真机「轻快」得多——
RL 策略学到的加速能力根本不存在。

---

## 二、为什么这件事非做不可

因为 sim2real 的 gap **就是这三样**。

```
仿真里的臂：无摩擦、转子惯量为 0   →  策略学会「轻轻一推就动」
真机上的臂：摩擦 0.2 N·m、反射惯量 0.013  →  同样的力矩，纹丝不动
```

⛔ **不辨识就训 RL，等于在一个不存在的世界里训练。**

---

## 三、⚠️ 一个必须避开的自欺

官方 SDK 提供了 `get_friction_compensation(vel, Fc, Fv, vel_threshold)`。
很容易想到：**把同一组 $F_c, F_v$ 既用于控制器补偿、又填进 URDF 当仿真摩擦。**

**⛔ 不行。** 这会让 sim 和 real「看起来对得很好」——因为两边用的是**同一组假数**。
真实 gap 一点没减少，只是被藏起来了。

> 这正是 armctrl 批次 E-2（P1-09）抓到的那个 bug：
> **补偿端和被控对象端共用同一个形变量 ⇒ 两端符号一起翻，误差分毫不变，8/8 测试全绿。**
>
> ⭐ 元教训：**用被测实现的中间量去证明它自己，是最常见的自欺方式。**

**正确做法**：辨识出来的参数**只填进仿真模型**；
评估 gap 时用**与补偿器无关的独立量**（见 §六）。

## 四、辨识流程

### 4.1 线性参数化

动力学对参数是**线性**的（14 篇 §8.2）：

$$\tau = Y(q,\dot q,\ddot q)\,\pi$$

对 Panthera，每个关节的参数向量含：

| 类别 | 每关节几个 | 说明 |
|---|---|---|
| 连杆惯性参数 | 10 | 质量、一阶矩、惯量张量 6 项 |
| **电机反射惯量** | 1 | ⭐ 要辨的重点之一 |
| **库仑摩擦** $F_c$ | 1 | ⭐ |
| **粘滞摩擦** $F_v$ | 1 | ⭐ |

⚠️ 连杆惯性那 10 个 CAD 已经给得不错，**真正要辨的是后 3 个**。
可以把 CAD 值当先验，只辨识传动项——自由度更少，条件数更好。

### 4.2 激励轨迹

参数辨识准不准，**取决于轨迹够不够「花哨」**（15 篇 §4.4 的持续激励 PE）。

用傅里叶级数轨迹，以**回归矩阵条件数**为目标优化：

$$q_i(t) = q_{i,0} + \sum_{k=1}^{K}
\left[\frac{a_{ik}}{k\omega_f}\sin(k\omega_f t) - \frac{b_{ik}}{k\omega_f}\cos(k\omega_f t)\right]$$

约束：关节限位、速度上限、**力矩不得超过 SDK 限幅**、不得自碰撞。

> ⭐ armctrl 里这条做到了条件数 $10^{18.25} \to 10^{2.54}$，代码可直接复用。

### 4.3 ⚠️ 采数据时的三个坑

| 坑 | 后果 | 对策 |
|---|---|---|
| **底座没固定死** | 底座柔性混进惯量估计 | ⭐ G 型夹夹紧 + 厚底板，**别省这一步** |
| $\ddot q$ 靠差分 | 噪声被放大 $1/\Delta t^2$ | 用带通滤波，或**只在低频谐波上做拟合** |
| 力矩读数是电流估算 | 含未建模的电机常数误差 | 记录为 `自报` 档，**不能用来自证** |

### 4.4 求解

用**增量 QR**，不要用 $G=W^{\mathsf T}W$：

> ⭐ armctrl 元教训 #26：$\kappa(G)=\kappa(W)^2$，条件数被平方后顶穿双精度，
> 会报出**逻辑上不可能**的秩。改用增量 QR 后答案立刻正常。

## 五、回填模型

辨识结果写进 MJCF：

| 辨识量 | MJCF 字段 |
|---|---|
| 反射惯量 | `<joint armature="...">` |
| 粘滞摩擦 $F_v$ | `<joint damping="...">` |
| 库仑摩擦 $F_c$ | `<joint frictionloss="...">` |
| 连杆惯性修正 | `<inertial>` |

改 `tools/urdf_to_mjcf.py` 里的 `ROTOR_INERTIA_GUESS` / `FRICTION_GUESS`，
**并把变量名里的 `_GUESS` 去掉**——那个后缀就是在提醒「这还没辨识」。

## 六、⭐⭐ 怎么证明它真的变好了（本篇最重要的一节）

「补上参数之后 gap 变小了」这句话，**必须由独立判据支撑**。

### 判据设计的规矩

> **判据不能来自被测对象自己。**（armctrl §九）

| ❌ 不能用 | 为什么 |
|---|---|
| 「补偿后力矩残差变小」 | 残差由补偿器自己算，是自证循环 |
| 「摩擦模型拟合得好」 | 拟合优度不等于预测能力 |
| 「仿真里跑得更像了」 | 仿真模型正是被改动的对象 |

| ✅ 可以用 | 为什么独立 |
|---|---|
| ⭐ **同一条力矩序列，开环下发**，比末端实际轨迹 | 不涉及任何反馈或补偿 |
| **留出验证轨迹**：辨识用 A 组，评估用 B 组 | B 组没参与拟合 |
| 阶跃响应的**上升时间/超调**对照 | 时域特征，与参数化形式无关 |

### 推荐的量化实验

```
① 选一条辨识时没用过的轨迹 B
② 在仿真里跑 → 记录末端轨迹 x_sim
③ 同一条力矩序列在真机开环下发 → 记录 x_real
④ gap = ‖x_sim − x_real‖  （随时间的曲线，不是单个数）
⑤ 分别用「CAD 模型」和「辨识后模型」各做一遍，对比两条 gap 曲线
```

⚠️ **报结果时必须带工况**：哪条轨迹、多大速度、什么姿态。
> armctrl 元教训 #18：**报误差之前先说清楚哪个工况**，
> 就像报秩之前先说清楚哪个回归矩阵。

## 七、然后才是 RL

模型补好了，再进 RL：

| 步骤 | 注意 |
|---|---|
| MJCF → USD | Isaac Sim 自带 URDF Importer；⚠️ 导入后**核对 armature 有没有丢** |
| 第一个策略选**状态型**，不要视觉 | ⭐ 视觉的渲染 gap 会盖过动力学 gap，你的核心贡献就说不清了 |
| 域随机化范围 | 以**辨识出的参数为中心**做扰动，而不是拍脑袋 |
| 部署 | 控制器侧才用摩擦补偿；⚠️ 记住它和仿真摩擦是**同源**的 |

⭐ **最终能讲出来的一句话**：

> 「官方 URDF 是 CAD 导出的，摩擦和转子反射惯量都是 0。
> 我用傅里叶激励轨迹做参数辨识，条件数从 X 优化到 Y，
> 回填模型后 sim2real 的末端轨迹偏差从 A 降到 B。
> **判据是独立的**——用的是留出验证轨迹的开环对照，不读补偿器的任何中间量。」
