# SDK 示例 vs 我们的项目：重叠在哪、还缺什么

> 回答两个问题：① 官方 SDK 的 30 个示例和我们要做的重叠吗？② 我们到底该做哪些项目？
>
> 关联：[方法可行性与岗位对照](方法可行性与岗位对照.md)（模块级）｜本篇是**示例级**对照

## 【一分钟速查】

| | |
|---|---|
| **重叠吗** | ⭐ **大量重叠，但重叠的地方不是浪费** |
| ⭐ **核心区别** | SDK 示例回答「**这个函数怎么调**」；岗位要的是「**这个算法为什么这么设计、真机上为什么不 work、怎么排查**」 |
| ⭐⭐ **正确用法** | 把 SDK 示例当作**对照基线**，每个模块都要能说清「我比官方示例多了什么」 |
| 🔴 **最大空白** | **拖动示教**、**安全停机**、**绝对精度**、**避障** —— 岗位逐字点名，SDK 有示例或没有，而**我们都还没做** |

## 一、先看清 SDK 给了什么

官方 `panthera_python/scripts/` 下 **30 个示例**，按编号分五档：

| 档 | 示例 | 本质 |
|---|---|---|
| `0_` | 读状态、设零位 | 硬件自检 |
| `1_` | 关节位置/速度/PD、moveJ、FK、IK | **基础 API 演示** |
| `2_` | 重力补偿、重力+摩擦补偿、关节阻抗（×2）、IK 位姿控制 | **力矩控制入门** |
| `3_` | 多项式插值（×2）、正弦跟踪、重力补偿+FK 显示 | **轨迹层** |
| `4_` | 轨迹级阻抗控制 | 组合 |
| `5_` | 拖动示教录制、轨迹回放、双臂主从遥操 | **应用** |
| `6_` | moveL 直线（位置/旋转） | 笛卡尔 |
| `7_` | 键盘/手柄/GELLO/VR 遥操（6 个） | **遥操作全家桶** |
| `motor_example/` | 单电机位置/速度/力矩/电压/电流/MIT（9 个） | 底层 |

### ⭐ 一句话定性

> **这 30 个示例是「功能演示」，不是「算法实现」。**
>
> 它们证明的是「**这台机器能做到**」，不是「**这个算法怎么设计**」。

举个最直接的例子 —— 官方的重力补偿示例，核心就 3 行：

```python
tor = robot.get_Gravity()                       # ← 模型是官方给的
tor = np.clip(tor, -tau_limit, tau_limit)
robot.pos_vel_tqe_kp_kd(zero_pos, zero_vel, tor, zero_kp, zero_kd)
```

⚠️ 这 3 行里，**你无法回答任何一个面试官会问的问题**：

* `get_Gravity()` 用的模型准不准？**误差多少？**
* 模型误差 10% 会怎样？（`实测` 3 秒漂 **108.6°**）
* 为什么要配 PD 而不是纯重力补偿？（`实测` 好 **10.1 倍**）
* 这个「10.1 倍」是巧合吗？（不是，$= 1/\epsilon$）

⭐⭐ **这就是我们项目存在的全部意义** —— 把「能跑」变成「能解释、能量化、能排查」。

## 二、逐项对照：SDK 示例 ↔ 我们的模块

### 2.1 ✅ 重叠且我们更深（这是好事，是「有基线可比」）

| SDK 示例 | 我们的模块 | ⭐ 我们多了什么（可写进简历/面试） |
|---|---|---|
| `1_Joint_PD_control` | `rollout.pd_controller` | 量化稳态误差 $e_{ss}=g/k_p$；J3 手算 1.726° vs `实测` 1.735° ✓ |
| `1_forward/inverse_kinematics_test` | `core/kinematics.py`（DLS IK）| 标定 $\sigma_0=0.004281$（Panda 的 0.48 倍）；发现 IK 速度**取决于初值距离**，连续跟踪 **5036 Hz** 而非最坏工况的 148 Hz |
| `2_gravity_compensation_control` | `robot.gravity()` + 讲义 17 | ⭐⭐ 证明**收益 $=1/\epsilon$**；证明**多补和少补一样坏**（3.54× vs 3.53×）|
| `2_Jointimpendence_*_with_gra_pd` | `control/impedance.py` | 扩到**笛卡尔阻抗 + 导纳 + 力位混合**；`实测` 去掉 bias 偏 95.11 mm |
| `3_interpolation_control_*` | `planning/trajectory.py` | ⭐ 发现**五次多项式超速 10.3%** —— 这就是工业界改用 S 曲线的原因 |
| `3_sin_trajectory_control` | `rollout.sine_reference` | 做成**闭环跑道**，能量化 RMS / 饱和率 / 超调 |
| `4_impedance_trajectory_control` | 同上组合 | — |
| `7_keyboard/gamepad/vr_*` | `teleop/spacemouse.py` | 加了**安全层**（6 道闸）和限位/奇异保护 |

> ⭐ **面试话术模板**：
> 「官方 SDK 有这个示例，我在它基础上做了三件事：**量化了它的误差来源**、**找出了它的失效边界**、**写了守护测试防止回归**。」

### 2.2 ⭐ SDK 完全没有，只有我们做了（项目的差异化）

| 我们的模块 | SDK 有吗 | 为什么重要 |
|---|---|---|
| **参数辨识全流程** `identification/`（激励轨迹 + 回归矩阵 + 基参数投影 + 最小二乘）| ❌ 完全没有 | 🔴 岗位 A/B **都逐字点名**「动力学建模与参数辨识」 |
| **计算力矩 CTC** `control/computed_torque.py` | ❌ 没有 | $M[0,0]$ 随姿态变 **35.9 倍**、耦合 **43.4%** —— PD 处理不了 |
| **Slotine-Li 自适应** `control/adaptive.py` | ❌ 没有 | 唯一带 Lyapunov 稳定性证明的 |
| **动量观测器 / 碰撞检测** `control/momentum_observer.py` | ❌ 没有 | 🔴 岗位 A 点名「碰撞检测」 |
| **TOPP 时间最优** `planning/topp.py` | ❌ 没有 | 🔴 岗位 A 点名「时间规划」 |
| **安全层** `driver/safety.py`（6 道闸）| ❌ 没有 | ⚠️ 官方三个硬件保护**默认全关** ⇒ 这是唯一保护 |
| **仿真闭环跑道** `sim/rollout.py` | ❌ 没有 | 所有量化结论的基础设施 |
| **调参台** `tuner/` | ❌ 没有 | 把「调参感觉」变成可复现实验 |

### 2.3 🔴 SDK 有示例、岗位点名、**而我们还没做**（← 这就是答案）

| SDK 示例 | 对应岗位要求 | 我们的状态 |
|---|---|---|
| `5_record_trajectory` + `5_replay_trajectory` | 🔴 岗位 A「**拖动示教**」、岗位 B 上肢「**拖动示教**」 | ❌ **没有代码** |
| `6_moveL_pos/rotate_control` | 岗位 A「插补算法」笛卡尔部分 | ⚠️ 只有关节空间 |
| `2_gravity_friction_compensation` | 岗位 A「力控」的前置 | ⚠️ 摩擦模型是**占位值**，要辨识 |
| `5_teleop_control`（双臂主从）| 岗位 B「全身动作跟随」的单臂版 | ⚠️ 需要第二条臂 |

### 3.3 ⭐⭐ 岗位 B 的优先条件第 3 条

> 原文：「具备机器人运控算法**真机落地**、**性能调优**经验，能够**独立排查算法及真机运动问题**者优先」

**这条正是我们现在每天在做的事**，而且已经有很硬的证据：

| 我们排查出来的问题 | 说明什么 |
|---|---|
| 🔴 底座与 link1 永久穿模 2.3mm，接触摩擦锁死 J1 —— **此前 51 项测试全过**（没一项闭合回路）| 会做闭环验证 |
| 🔴 `mj_fullM` 绑定被来回改错三次，根因是**版本号 3.12 被读成 3.2** | 能定位到根因而非表象 |
| 🔴 TCP 改了 24.3mm 而 **170 项测试照常全过** ⇒ 判据缺失 | 知道「测试通过 ≠ 正确」 |
| ⭐ 训练残差 **0.046%** 而真实参数误差 **49.9%** | 判据必须独立于被测对象 |
| ⭐ 「3.44× 改善」重跑变 1.01× —— 发散系统的混沌轨迹 | 会怀疑自己的好结果 |

> ⭐ **这些「排查故事」比任何算法本身都更贴题**。面试时它们是最有说服力的部分。

## 四、所以我们要做什么项目

### 4.1 排序原则

按 **(岗位点名权重 × 真机可演示性) ÷ 成本** 排。

### 4.2 🔴 P0 —— 本周做完（都是「岗位点名 + 我们空白」）

| # | 项目 | 为什么排第一 | 产出 |
|---|---|---|---|
| **1** | **上电与实测控制频率** | ⭐ 一个数决定后面**所有**增益、看门狗、延迟预算 | `connect_check.py` 的三个数 |
| **2** | **参数辨识跑通真机** | ⭐ 我们的王牌，岗位 A/B 都点名 | 真实 $\epsilon$，回填模型 |
| **3** | **拖动示教** | 🔴 岗位 A/B 都点名，**SDK 有示例可对照，成本最低** | 录制+回放+精度评估 |

> ⭐ 第 3 项的做法：**先跑官方 `5_record_trajectory.py`，再写我们的版本**，然后回答官方版本回答不了的问题 ——
> 「回放精度是多少？」「零力矩拖动时摩擦有多大影响？」「录 10 分钟会漂多少？」

### 4.3 🟡 P1 —— 真机可演示（两周）

### 4.4 🟢 P2 —— 加分项（一个月）

| # | 项目 | 备注 |

| 不做 | 原因 |

## 五、简历上怎么讲这三个项目

| 项目 | 主打 | 对应岗位 |
|---|---|---|
| ⭐ **Panthera 六轴臂** | **真机落地 + 独立排查** + 辨识 + 力控 | 岗位 A 主体 / 岗位 B 方向一 |
| **人形运控** | 全身平衡、状态估计、步态 | 岗位 B 方向二 |
| **空中机械臂** | 浮动基座、强耦合、抗扰 | 差异化亮点 |

⭐ **Panthera 的定位不是「armctrl 的真机版」**，而是：

> **「同一套算法，我在仿真和真机上都跑过，并且能说清两边差在哪、为什么差。」**

这正好命中岗位 B 优先条件第 3 条。

## 六、⚠️ 一条容易走偏的路

> ⛔ **不要把 30 个 SDK 示例挨个跑一遍然后说「我都会」。**

那证明的是「你会读 README」。

✅ **正确做法**：每挑一个示例，问它三个问题 ——

1. **它的误差是多少？** （官方示例从不给这个数）
2. **它什么时候会失效？** （边界在哪）
3. **失效了怎么排查？** （这是岗位真正要的）

⭐ 我们讲义里每一篇的「**三个动手实验**」和「**边界与常见误解**」两节，就是照这个模板写的。
