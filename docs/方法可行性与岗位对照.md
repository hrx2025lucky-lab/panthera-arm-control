# armctrl 方法 → Panthera 真机可行性 + 岗位对照

> 三个问题一起答：
> ① armctrl 的方法能不能都在 Panthera 上测
> ② 汇川要哪些
> ③ Panthera 项目该定位成什么

---

## 一、结论先说

| 问题 | 答案 |
|---|---|
| **能都测吗** | ⚠️ **不能**。18 个模块里 **11 个能测、4 个要改、3 个测不了** |
| **汇川要什么** | 岗位 B 点名 17 项算法，armctrl 命中 13；⭐ **岗位 A 的优先条件第 3 条才是关键** |
| **Panthera 定位** | ⭐ **不是"再做一遍"，是"把仿真结论推到真机"** |

⭐ **最重要的一句话**：

> 岗位 A 优先条件第 3 条：「具备机器人运控算法**真机落地、性能调优经验**，
> 能够**独立排查算法及真机运动问题**者优先」

armctrl 再完整也只是仿真。**Panthera 存在的全部意义就是这一条。**

## 二、逐个模块：能不能在 Panthera 上测

### ✅ 能直接测（已迁移，7 个）

| 模块 | 真机验证方式 | 状态 |
|---|---|---|
| **重力补偿** | 手臂不下垂、能推动 | ✅ 代码就绪 |
| **参数辨识** | ⭐ 辨识出转子惯量，与 CAD 比 | ✅ 就绪 |
| **计算力矩 CTC** | 同力矩预算下 vs PD | ✅ 就绪 |

| **动量观测器** | ⭐ 挂已知砝码，看能否估出来 | ✅ 就绪 |
| **拖动示教** | 手推手臂，测阻力 | ✅ 就绪 |

### 🟡 能测但要改（4 个）

### 🔴 测不了或价值有限（3 个）

## 三、汇川到底要什么

### 岗位 B（工业机器人）：17 项逐字点名

| | armctrl | Panthera 能做到 |
|---|---|---|
| ✅ 已覆盖 13 项 | 仿真验证 | ⭐ **真机验证** |
| ⚠️ 绝对精度 | 只注入误差被学掉，无标定流程 | 🟡 可做（需要外部测量）|
| ❌ 安全停机/故障诊断 | 零实现 | ⭐⭐ **Panthera 上必须做**（见下）|
| ❌ 工艺 | 概念 | ❌ 不做（需要焊接/喷涂设备）|

⭐⭐ **安全停机 / 故障诊断是最值得补的空白**，因为：

1. 岗位 B **逐字点名**
2. ⭐ 我们**已经做了一半**——`SafetyLayer` 就是安全停机
3. ⭐⭐ 这台机器**没有急停按钮、没有抱闸、三项保护默认关闭**
   ⇒ **真机上这件事有真实的必要性**，不是为了简历硬做

> 面试时能说：「这台机器没有硬件急停，我实现了软件看门狗 +
> 上电斜坡 + 限位刹车 + 故障锁存，并用变异测试验证了每一道闸真的会拦」
> ——这比「我了解安全停机的概念」强一个数量级。

## 四、⭐ Panthera 项目该怎么定位

### ❌ 不要定位成"armctrl 的真机版"

那样别人会问："那和 armctrl 有什么区别？"

### ✅ 定位成三件别人做不了的事

#### ① **系统辨识 vs 域随机化的定量对照**（主线）

| | 传统控制 | 学习控制 |
|---|---|---|
| **精确模型** | 辨识 + CTC | 辨识后模型做 RL |
| **不精确模型** | 名义模型 + PD | 域随机化 + RL |

⭐ 这个问题**学术上有争议、工业上有实际意义**，而且**必须有真机才能回答**。

⇒ 一句话总结：**"当你有一台真机和有限时间，知识该注入到哪一层？"**

#### ② **真机排查能力的证据链**

这个项目已经积累了一批**别人复制不了的发现**：

| 发现 | 为什么有说服力 |
|---|---|
| 官方限幅**超额定 100%**，而辨识要连跑 10 分钟 | 查了客服答复 + 算了数 |
| 官方阻抗刚度是 armctrl 的 1/21，注释写"避免**再次**激励腕部抖动" | 读了源码注释 |
| TCP 定义有**三个版本**，我们用错了 24 mm | 核对了三个仓库 |
| link5/link6 惯量 SDK 与 ROS2 差 **221%** | 客服警告过，我们定位到了具体位置 |
| 底座与 link1 **永久穿模**锁死 J1，51 项测试全绿 | ⭐ 闭环仿真才抓得到 |
| 一个"3.44× 改善"重跑变成 1.01× | ⭐ **同一实验做两遍** |

⭐⭐ **这一列才是"独立排查真机运动问题"的证据。**
不是"我会阻抗控制"，而是"**我能发现别人没发现的问题，并且证明它是真的**"。

#### ③ **补 armctrl 的空白：安全停机 + 故障诊断**

⭐ 有真实必要性（无急停、无抱闸、保护默认关闭），不是硬做。

## 五、简历三个项目怎么分工

你说以 **Panthera + 空中机械臂 + 人形运控** 为主。建议这样分：

| 项目 | 讲什么 | 命中 |
|---|---|---|
| **空中机械臂**（毕设） | ⭐ **建模 + 多控制器对比**（Simulink）| 岗位 A 技能要求点名 Simulink |
| **人形运控** | ⭐ **步态 + 全身平衡 + RL** | 岗位 A 优先条件① |
| ⭐ **Panthera** | ⭐⭐ **真机落地 + 辨识 + 力控 + 排查** | 岗位 A 优先条件②③、岗位 B 全部 |

⭐ **三个项目正好覆盖三种能力**：

```
空中机械臂 → 建模与仿真能力（会算）
人形运控   → 前沿算法能力（会学）
Panthera   → 真机工程能力（会做）  ← ⭐ 最稀缺
```

⚠️ **不要三个都讲"我实现了阻抗控制"** —— 那样显得只会一件事。

### armctrl 怎么处理

⭐ **armctrl 不单独作为一个项目，而是作为 Panthera 的"前置"**：

> 「我先在 Franka Panda 仿真上把 13 类控制方法做了一遍并经五轮审核，
> 然后买了真机，把结论推到真机上验证——过程中发现仿真里成立的结论
> 有几条在真机上是错的。」

⭐ 这个叙事比"我做了两个项目"强，因为它体现的是**方法论**。

## 六、接下来的优先级建议

| 顺序 | 做什么 | 理由 |
|---|---|---|
| **1** | ⭐ 上电 + 辨识 + CTC/阻抗真机验证 | 项目主线，也是"真机落地"的证据 |
| **2** | planning 迁移（IK/插补/轨迹） | ⭐ 岗位 B 点名多、成本低、演示直观 |
| **3** | ⭐ 安全停机 + 故障诊断做完整 | 补空白，有真实必要性 |
| **4** | RL sim2real + 四象限对照 | 项目最终目标 |
| **5** | 视觉抓取（D405） | 加分项，非核心 |

⚠️ **不建议做的**：工艺算法（要设备）、力位混合（无力传感器）、
零空间相关（6 轴没有）。
