## 一、任务：跟一条什么样的轨迹

### 1.1 参考轨迹是一个显式时间函数

它规定「每一时刻 TCP 该在哪」：

$$p_{\text{ref}}(t)\in\mathbb{R}^3$$

最简单的圆：

$$p_{\text{ref}}(t)=p_c+R\begin{bmatrix}\cos\omega t\\ \sin\omega t\\ 0\end{bmatrix},
\qquad \omega=\frac{2\pi}{T}$$

**三个硬要求**

| 要求 | 为什么 |
|---|---|
| **二阶连续可导** | ⭐ CTC 要用 $\ddot p_{\text{ref}}$ 做前馈。不可导就没法和 RL 公平比 |
| 全程在工作空间内、不自碰撞 | —— |
| ⭐ **速度足够快** | 慢了动力学不起作用，四象限会全部一样 |

### 1.2 参数怎么选（用本仓库模型算出的实际数）

圆心取 `Q_HOME` 处的 TCP `[0.3304, 0, 0.308]`（离底座 0.452 m），半径 0.10 m：

| 周期 T | TCP 速度 | TCP 加速度 | 最大关节速度 | 评价 |
|---|---|---|---|---|
| 4.0 s | 0.157 m/s | 0.25 m/s² | 0.78 rad/s | ⛔ 太慢，摩擦与惯量都无所谓 |
| **2.5 s** | 0.251 m/s | 0.63 m/s² | 1.24 rad/s | ⭐ **推荐起点** |
| 1.5 s | 0.419 m/s | 1.75 m/s² | 2.07 rad/s | 🟠 激进版，用于对照 |

关节速度上限为 4.2 / 5 / 5 / 4.2 / 3.7 / 3.7 rad/s，上面三档都有充足余量。

**形状建议**：先用**圆**跑通流程；辨识和最终评估用 **8 字（Lissajous）**，
因为它激发更多关节、频谱更丰富。

### 1.3 ⭐⭐ 前提检查：任务对动力学够不够敏感

**选定周期后、开始训练前，必须先做这一步。**

```
在仿真里用 CAD 模型 和 辨识后模型 各跑一遍同一条轨迹，比较 TCP 轨迹差异。
```

| 结果 | 结论 |
|---|---|
| 两条轨迹差异明显 | ✅ 任务合格，继续 |
| ⛔ 几乎重合 | **任务太慢，整个对照实验不成立**——四个格子会给出相同结果 |

> ⭐ **任务的速度是实验设计的一部分，不是随便定的。**
> 跳过这一步，可能白训两周才发现什么都比不出来。

## 二、⚠️ 抓取任务为什么不做第一个

看 gap 的来源构成：

| 任务 | gap 来自哪几项 |
|---|---|
| **轨迹跟踪** | ⭐ **只有动力学**（摩擦、惯量、延迟） |
| 视觉抓取 | 动力学 **＋ 渲染差异 ＋ 接触模型 ＋ 物体位姿估计误差** |

我们要量的是「**辨识让动力学 gap 降了多少**」。视觉抓取把四项混在一起，
**分不清改善来自哪一项**——判据被污染。

> armctrl 元教训 #10：「我这个判据，除了我关心的那个原因，
> 还有别的原因能让它变化吗？」——有，而且有三个。

**分阶段路线**

| 阶段 | 任务 | 需要的硬件 | gap 来源 |
|---|---|---|---|
| **1** | ⭐ 轨迹跟踪（四象限对照） | 只要臂 | 动力学 |
| 2 | **状态型抓取**：物体位姿直接给，不用视觉 | ＋夹爪 | 动力学 ＋ 接触 |
| 3 | 视觉抓取 | ＋D405 | 全部四项 |

⭐ 阶段 2 是很好的中间站：保留接触与夹爪、去掉渲染 gap，
还能引出新问题——**接触模型的 gap 和动力学的 gap 哪个更大**。

⇒ **阶段 1、2 都用不到深度相机**，D405 可以推迟购买。

## 三、八步流程

### 第 1 步　模型准备

```
官方 URDF ──┬──→ MJCF (MuJoCo)    ✅ 已完成，tools/urdf_to_mjcf.py
            └──→ USD  (Isaac Sim) ← URDF Importer
                      ↓
               物理指纹逐项 diff  ← tests/test_model_parity.py
```

⚠️ **导入 USD 后必须核对 `armature`**——它不是 URDF 标准字段，
各家导入器处理方式不一，**最容易悄悄丢掉**。

丢了以后的后果很隐蔽：sim2sim 对不上 → 你以为是「引擎差异」→
实际是「模型没对齐」。两种原因混在一起，第 7 步的判据就废了。

### 第 2 步　定义 MDP

**观测（要和 CTC 信息对等）**

```python
obs = concat([
    q,               #   6  关节位置
    qd,              #   6  关节速度
    a_prev,          #   6  上一步动作（策略要知道自己刚做了什么）
    ref_future,      # 6×N  参考轨迹未来 N 步 ← ⭐ 别漏
])
```

⚠️⚠️ **只放真机上拿得到的量。**
仿真里有、真机没有的（真实外力、真实摩擦系数、物体真值位姿）
**绝对不能进 obs**——那叫特权信息，策略会在真机上当场失效。

> ⭐ 为什么要给 `ref_future`：CTC 知道完整参考轨迹（含 $\ddot p_d$ 做前馈）。
> 不给 RL 未来信息，就是人为削弱它，对照不公平。

**动作（legged 标准范式）**

```python
a ∈ [-1, 1]^6
q_target = q_default + a * action_scale     # action_scale ≈ 0.25 rad
```

下发：`pos_vel_tqe_kp_kd(q_target, 0, 0, kp, kd)`

⭐ **不要让策略直接输出力矩**——对延迟和噪声太敏感，sim2real 极难过关。
这也是腿足圈的通行做法（你 G1 项目就是这样）。

**奖励（保持简单）**

```python
r = -‖p_tcp - p_ref‖                  # 主项：跟踪
    - 0.001 * ‖tau‖**2                # 正则：别太暴力
    - 0.01  * ‖a_t - a_{t-1}‖**2      # 正则：动作别抖
```

⚠️ 正则权重要**小**，别盖过主项。

⚠️ 注意一个**偏向 RL 的不公平**：主项就是评估指标，
等于 RL 在直接优化考试题，而 CTC 是间接达成。
⭐ **不要为了"公平"去削弱 RL——在结论里如实说明，比人为拉平更诚实。**

**终止条件**：超关节限位 / 速度超限 / 误差发散。

### 第 3 步　⚠️ 仿真的执行器模型必须和真机一致

**这是最容易出错的一步。**

真机的 PD 在电机模组内部以 3 kHz 执行，仿真里必须复现：

```python
# 每个物理步都执行，不是每个策略步
tau = kp * (q_target - q) - kd * qd
tau = np.clip(tau, -tau_limit, tau_limit)    # ⭐ 限幅必须在里面
```

⭐ **三个频率要分清**

| 层 | 频率 | 谁在跑 |
|---|---|---|
| 策略推理 | **50 Hz** | Python |
| PD 环 | 1 kHz（仿真）/ **3 kHz（真机电机内部）** | 底层 |
| 物理积分 | 500 Hz ~ 1 kHz | MuJoCo / PhysX |

⚠️ **kp / kd 在仿真和真机必须完全一致**，并写进物理指纹一起 diff。

### 第 4 步　域随机化

⭐ **以辨识出的参数为中心，而不是拍脑袋。**

| 随机什么 | 建议范围 | 理由 |
|---|---|---|
| **关节摩擦** $F_c, F_v$ | 辨识值 **±2σ** | 头号 gap 来源 |
| **转子惯量** armature | ±20% | 占位值本来就不准 |
| 连杆质量 | ±5% | CAD 较准，给小范围 |
| **PD 增益** kp / kd | ±10% | 真机电机实际增益有偏差 |
| **动作延迟** | 0 ~ 2 个策略步 | ⭐ CAN 往返 + 零阶保持 |
| 观测噪声 | 编码器量化级 | —— |

⚠️ **别随机化重力方向、别随机化关节限位**——那些是确定量，
随机化只会让策略变保守，白白损失性能。

### 第 5 步　训练（IsaacLab）

- PPO，数千并行环境
- ⚠️ **至少 3~5 个随机种子**，报均值与方差。单种子结果说明不了任何问题
- 记录：训练曲线、最终奖励、成功率、**所用随机化配置**

### 第 6 步　导出策略

```python
torch.onnx.export(policy, dummy_obs, "policy.onnx")
```

⚠️⚠️ **必须把 obs 的归一化参数（均值 / 方差）一起导出。**

> 这是 sim2real 最常见的翻车点：ONNX 只存网络权重，
> 归一化是在网络外面做的。忘了带，策略输入分布完全错位，行为一塌糊涂。

### 第 7 步　⭐ sim2sim 验证（不能跳）

```
IsaacLab 训出的 policy.onnx  →  放进 MuJoCo 跑同一个任务
```

| 结果 | 结论 |
|---|---|
| MuJoCo 里表现接近 | ✅ 策略学到的是物理，可以考虑上真机 |
| ⚠️ 明显变差 | ⛔ **过拟合到 PhysX 的数值特性了，不要上真机** |

⭐ **这一步就是「判据独立」**：IsaacLab 用 PhysX、MuJoCo 用自己的求解器，
是两套独立实现，**同时错的概率很低**。

⚠️ 若 sim2sim 对不上，**先查模型是否对齐**（armature 丢了？kp/kd 不一样？），
再怀疑策略。这正是物理指纹存在的意义。

### 第 8 步　真机部署

⛔ **上电前四件事（顺序不能反）**

1. **实测控制频率**——官方示例 `sleep(0.002)` 是期望值不是实测值
2. **单关节先行**，从 `tau=0` 起步，手放急停旁
3. **看门狗**：控制循环卡住时自动置零力矩
4. **验证限幅生效**：故意下发超限力矩，确认被截断而不是被执行

**部署顺序**

```
① 策略照常输出，但 kp 调小（更软）跑一遍，观察行为是否合理
② 逐步把 kp 恢复到训练时的值
③ 录制 TCP 实际轨迹 → 算 RMS 误差
④ 与仿真中同一条轨迹对比 → 这个差值就是 sim2real gap
```

## 四、部署架构：不必上板卡

Panthera 随机附带的**「通用盒子底板（7 路 CAN 板）」**：
包装清单标注 **「无系统」**（出厂不带操作系统），
有拨码开关切换 **内部系统算力 / 外部主控算力**，7 路 CAN FD。

| 方案 | 怎么跑 | 评价 |
|---|---|---|
| ⭐ **A. 你的 Linux 电脑** | USB-CAN 连臂，ONNX 在 PC 上推理 | **推荐，先用这个** |
| B. 底板内部算力 | 自己装系统，策略跑在板上 | 以后要脱机运行时再说 |
| C. 外接 Jetson | 板子切「外部主控」 | 要移动 / 嵌入式时 |

```
PC (ONNX, 50 Hz) ──USB──→ CAN 板 ──CAN FD 5 Mbps──→ 6 个电机模组 (PD @ 3 kHz)
        ↑                                                    │
        └──────────────────── 状态反馈 ─────────────────────┘
```

⭐ **为什么 A 就够**：策略是输入几十维、输出 6 维的小 MLP，50 Hz 推理，
**普通笔记本 CPU 绰绰有余**，不需要 GPU，也不需要板卡算力。

真正的瓶颈从来不是推理算力，而是 **CAN 往返延迟**——
这也是「上电前四件事」把实测频率排第一的原因。

## 五、接回四象限对照

| 格 | 怎么跑 |
|---|---|
| **A / B**（CTC） | 在两套模型上分别标定 $M, C, g$，跑同一条轨迹 |
| **C / D**（RL） | 上面八步走两遍：一遍用 CAD 模型训，一遍用辨识模型训 |
| 评估 | ⭐ **四格跑同一条轨迹，比同一个 TCP RMS 误差** |

⚠️ 评估轨迹**不得参与辨识，也不得出现在 RL 训练分布中**。
