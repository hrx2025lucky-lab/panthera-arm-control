# 系统辨识 vs 域随机化：两条应对 sim2real gap 的路线对照

> **这一篇是本项目的最终目标**，也是它区别于「买个臂跑通 RL」的地方。
>
> 前置：[`参数辨识与sim2real.md`](参数辨识与sim2real.md)（辨识怎么做）、
> armctrl 讲义 14 篇 §八/§九（回归矩阵与激励轨迹）、15 篇 §四（稳定判据）。

---

## 一、问题：同一个 gap，两种应对哲学

官方 URDF 是 CAD 导出的，**摩擦为 0、转子反射惯量为 0**
（后者本该是 0.013 kg·m²，相当于 link2 惯量的 **57%**）。
仿真和真机因此对不上——这就是 sim2real gap。

对它有两种截然不同的处理方式：

| | **传统控制**（本项目的 CTC / 阻抗 / 自适应） | **RL + 域随机化** |
|---|---|---|
| 哲学 | **消灭 gap**：把模型做准 | **绕过 gap**：让策略在一堆模型上都能用 |
| 需要什么 | 参数的**点估计**要准 | 参数的**分布**要合理 |
| 典型失败 | 模型错 ⇒ 前馈补偿**方向就错** | 范围拍太宽 ⇒ **策略保守、性能下降** |
| 对负载变化 | 敏感（除非上自适应） | 鲁棒（若已随机化过） |

### ⭐ 一个常被忽略的前提

「RL 不需要精确模型」这句话**只对了一半**。

准确说法是：**RL 不需要精确的点估计，但需要合理的分布。**

> 摩擦到底是 0.05 还是 0.5？不知道 ⇒ 只能按 `[0.01, 1.0]` 随机化，
> 策略为了"什么都能应付"而变得畏手畏脚。
>
> 辨识出来是 `0.18 ± 0.02` ⇒ 范围收到 `[0.14, 0.22]` ⇒ **策略可以更激进**。

⇒ **辨识对两条路线都有用，只是作用点不同**：
传统控制拿它做**前馈**，RL 拿它**定随机化范围**。

**本篇要做的，就是把这句话从「说法」变成「数字」。**

## 二、主实验：四象限

在真机上跑**同一组评估轨迹**，比同样的指标。

|  | **CAD 模型**（摩擦=0、armature=0） | **辨识后模型** |
|---|---|---|
| **传统控制**（CTC / 阻抗） | **A** | **B** |
| **RL + 域随机化** | **C** | **D** |

### 每格看什么

| 对比 | 预期 | ⭐ 为什么值得做 |
|---|---|---|
| **A → B** | 大幅改善 | CTC 直接吃 $M,C,g$，改善应最明显。**验证辨识确实有效** |
| **A → C** | ⭐ C 明显好于 A | **同样是烂模型，RL 扛得住、CTC 扛不住**——最能说明域随机化的价值 |
| **C → D** | 改善较小 | ⭐⭐ **本实验的核心问题**：<br>D ≈ C ⇒ 域随机化确实能替代辨识<br>D ≫ C ⇒ 「不需要精确模型」被高估了 |
| **B vs D** | ？ | 两条路线都"用好了"之后，谁更强 |

> ⭐ **不管结果往哪边倒都有价值**——这是好实验的标志。
> 如果只有一个方向的结果算"成功"，那说明你在找证据支持预设结论，不是在做实验。

## 三、比四个点更有信息量：随机化宽度扫描

固定用辨识结果做中心，**扫描域随机化的宽度**：

```
横轴：随机化范围（以辨识出的 σ 为单位）
      ±0σ  →  ±1σ  →  ±3σ  →  ±10σ  →  拍脑袋的宽范围
纵轴：真机上的任务表现
```

**预期是一条倒 U 形曲线**：

| 范围 | 会发生什么 |
|---|---|
| **太窄**（±0σ，等于不随机化） | 过拟合到那一组参数，真机上崩 |
| ⭐ **合适**（±1~3σ） | 最优点 |
| **太宽**（拍脑袋） | 策略过于保守，性能下降 |

⭐⭐ **这条曲线就是「辨识对 RL 值多少钱」的定量答案**：
最优点比"拍脑袋宽范围"好多少，就是辨识带来的收益。

⚠️ **而画出这条曲线的前提是知道 σ 是多少——只有辨识能给。**
这一点本身就回答了「RL 是不是不需要辨识」。

## 四、加一维：未建模负载下的鲁棒性

四个格子训练/标定完成后，在末端挂一个**未建模的负载**（例如 0.5 kg），
不重新辨识、不重新训练，直接再跑一遍评估。

| 方法 | 预期 | 说明 |
|---|---|---|
| CTC + 辨识模型 | ⚠️ 明显变差 | 模型里没有这个负载 |
| **CTC + 自适应**（讲义 03 篇） | ⭐ 应能恢复 | 在线估参数 |
| RL + 窄随机化 | 变差 | 没见过这种情况 |
| RL + 宽随机化 | ⭐ 应最扛 | 训练时见过类似扰动 |

⭐ **这一格能引出一个好问题**：

> **自适应控制和域随机化，本质上是不是一回事？**
> 一个**在线**估参数并修正，一个**离线**把所有可能参数都练一遍。
> 前者需要持续激励（PE）条件，后者需要覆盖真实分布。

（面试里这是能聊很久的题目，而且你两边都做过。）

## 五、⚠️ 方法论前提（不满足则结论无效）

### 5.1 控制变量

* 四个格子用**同一组评估轨迹**、同样的初始条件、同样的指标
* ⚠️ **评估轨迹不得参与辨识**，也**不得出现在 RL 的训练分布里**
* 真机实验要**同一天、同一温度**做完——电机温度会显著改变摩擦

### 5.2 判据必须独立

> **判据不能来自被测对象自己。**（armctrl §九）

| ❌ 不能单独用 | 为什么 |
|---|---|
| 闭环跟踪误差 | 是控制器自己在闭环里的表现，各方法的闭环结构不同，不可比 |
| 「补偿后力矩残差小」 | 残差由补偿器自己算，自证循环 |
| 真机 `get_current_torque()` | 电流×固定系数估算，属 `自报` 档 |

| ✅ 应当用 | 为什么独立 |
|---|---|
| ⭐ **开环对照**：同一条指令序列开环下发，比末端实际轨迹 | 不涉及任何反馈 |
| **留出验证轨迹** | 没参与辨识、没参与训练 |
| 外部测量（若有相机/激光） | 完全独立于机器人自身读数 |

### 5.3 RL 的种子

⚠️ **至少 3~5 个随机种子，报均值和方差。**

> 单个种子的结果说明不了任何问题——这是 RL 领域最常见的自欺，
> 和 armctrl 元教训 #6「指标恒等于某个数通常意味着没在测」是同一类病。

### 5.4 ⚠️ 一个具体的陷阱

SDK 提供了 `get_friction_compensation(vel, Fc, Fv, ...)`。

⛔ **不要**把同一组 $F_c, F_v$ 既用于控制器补偿、又填进仿真当摩擦——
那样 sim 和 real 会「看起来很对」，因为两边用的是**同一组数**。

> armctrl 批次 E-2（P1-09）的同类陷阱：
> **补偿端和被控对象端共用同一个量 ⇒ 两端一起翻，误差分毫不变，8/8 测试全绿。**

## 六、实施顺序

```
① 参数辨识                        → 得到 π̂ 和它的不确定度 σ
② 建两套模型：CAD 版 / 辨识版      → 物理指纹逐项 diff（test_model_parity）
③ 格 A、B：CTC 在两套模型上标定    → 真机评估
④ 格 C、D：RL 在两套模型上训练      → sim2sim → 真机评估
⑤ 宽度扫描（§三）                  → 倒 U 曲线
⑥ 负载鲁棒性（§四）                → 四方对照
```

⚠️ **①必须最先**：没有 σ，第⑤步的横轴就没有刻度，只能拍脑袋。

## 七、这个作品的定位

**一句话**：

> 「面对同一个 sim2real gap，模型法和学习法各自怎么应对？我做了定量对照。
> 结论是域随机化**不能完全替代**系统辨识——它把辨识的角色从
> 『提供点估计』变成了『提供分布范围』，而范围定得准不准，
> 直接决定策略是激进还是保守。」

⭐ **为什么别人很难做这个实验**——它同时要求三样：

| 要求 | 你的储备 |
|---|---|
| 完整传统控制栈 + 参数辨识 | `armctrl`（13 篇讲义、734 测试、五轮审核） |
| RL 训练与 sim2real 部署 | G1 课程实践 + 毕设（IsaacLab、PPO/MAPPO） |
| 能跑力矩控制的真机 | Panthera-HT |

⭐ **这个实验把简历上原本分开的两条线（运控 / RL）拧成了一条。**
