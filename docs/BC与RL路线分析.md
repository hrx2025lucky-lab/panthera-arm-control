# 有了 D405 + SpaceMouse 之后能做什么

> 结论先说：**能做的事多了一整条路线（BC），而且它和 RL 能共享部署代码。**
>
> 分析基于官方四个仓库的源码，不是宣传页。

---

## 一、⭐⭐ 最重要的发现：BC 和 RL 的动作空间是同一个

官方 `Panthera-HT_lerobot` 里 `PantheraLeader.action_features` 返回：

```python
{f"{name}.pos": float for name in self.joint_names}
# → {"joint1.pos", ..., "joint6.pos", "gripper.pos"}
```

**动作 = 关节位置目标。**

而 RL 的标准做法也是**输出关节位置目标**，由电机侧 PD（MIT 模式 kp/kd）执行：

$$\tau = k_p(q_{des}-q) + k_d(\dot q_{des}-\dot q) + \tau_{ff}$$

⭐ **两者是同一个动作空间。** 这带来三个直接后果：

| 后果 | 说明 |
|---|---|
| **部署代码可共享** | `RealBackend.send_mit()` 一个接口同时服务 BC 和 RL |
| **可以公平对比** | 同任务、同动作空间、同硬件接口 —— 差异只来自策略本身 |
| ⭐ **BC 能给 RL 做初始化** | 这是 BC+RL 的标准玩法，见 §三 |

## 二、官方已有什么 / 缺什么

### ✅ 已有（可以直接用）

| 能力 | 出处 | 说明 |
|---|---|---|
| **LeRobot 集成** | `Panthera-HT_lerobot` | ⭐ BC 框架现成，含数据采集/训练/评估 |
| **模仿学习管线** | `Panthera-HT_RoboTwin` | ACT / Pi0 / RDT / DP / DP3 数据转换 |
| **视觉方案** | `Panthera_HT_SDK_Extensions` | D405 手眼标定 + YOLO + PBVS + GraspNet |
| **轨迹录制/回放** | SDK `5_record_trajectory.py` | 基础数据采集 |
| **笛卡尔速度遥操** | SDK `7_gamepad_*.py` | ⭐ 含 jerk 限制 + 绝对截止时间调度 |

### ❌ 缺什么（需要我们做）

| 缺口 | 为什么缺 | 工作量 |
|---|---|---|
| **SpaceMouse 适配** | 官方搜索结果 **0**。官方 teleop 是**主从双臂**（要两台机器） | 中 |
| **强化学习** | 官方只有模仿学习，无 RL | 大（本项目主线）|
| **IsaacLab 环境** | 官方只有 SAPIEN | 中 |
| **参数辨识** | 摩擦是经验值，注释写"需自行辨识" | ✅ 已完成 |
| **安全层** | 硬件保护默认关闭 | ✅ 已完成 |

⚠️ **官方 teleop 需要两台机器**（`panthera_leader` + `panthera_follower` 主从同构映射）。
我们只有一台，所以 SpaceMouse 不是"锦上添花"，而是**采数据的唯一途径**。

## 三、⭐ 新解锁的路线：BC + RL

### 3.1 为什么 SpaceMouse 是关键

BC（行为克隆）需要**人类示教数据**。没有遥操设备，就采不到数据，BC 无从谈起。

```
SpaceMouse → 人类演示 → 数据集 → BC 训练 → 策略
                                      ↓
                              RL 用它做初始化/正则
```

### 3.2 BC 和 RL 各自的长短

| | BC | RL |
|---|---|---|
| 数据来源 | 人类示教（贵、少） | 仿真采样（便宜、多） |
| 需要奖励函数 | ❌ 不需要 | ✅ 需要设计 |
| 需要仿真 | ❌ 不需要 | ✅ 需要（且有 sim2real gap） |
| 超出示教分布 | ⚠️ **崩溃**（compounding error） | ✅ 有一定泛化 |
| 学到人的偏好 | ✅ 天然 | ⚠️ 要写进奖励 |
| 上手速度 | ⭐ **快**（几十条演示就能动） | 慢（要训练 + sim2real）|

⭐ **BC+RL 的标准组合**（三选一，按难度）：

1. **BC 预训练 + RL 微调** —— 最常见。BC 给一个能动的起点，RL 提升成功率
2. **BC 作为 RL 的正则项** —— 防止 RL 探索到危险动作（真机上尤其重要）
3. **残差 RL** —— RL 只学 BC 的"修正量"，$a = a_{BC} + a_{RL}$，最安全

⚠️ 对我们这个项目，**②③ 比 ① 更有价值**——因为我们要在**真机**上做，
而纯 RL 在真机上探索是危险的。

### 3.3 这如何扩展我们的四象限实验

原来的四象限：

| | 传统控制 | 学习控制 |
|---|---|---|
| 精确模型 | 辨识 + CTC | 辨识后模型做 RL |
| 不精确模型 | 名义模型 + PD | 域随机化 + RL |

⭐ 现在可以加一行 **"不需要模型"**：

| | 需要模型 | **不需要模型** |
|---|---|---|
| **有先验知识** | 辨识 + CTC | ⭐ **BC（人类先验）** |
| **无先验知识** | 域随机化 + RL | 纯 RL（真机上不可行）|

这让实验变成一个更完整的**"知识从哪来"**的对照：
物理建模 / 数据辨识 / 人类示教 / 环境交互。

⭐ 这个框架比原来的四象限**更有讲头**，因为它回答了一个更本质的问题：
**当你有一台真机和有限时间，应该把知识注入到哪一层？**

## 四、架构：主控用电脑（不用板卡）

用户确定**机械臂直接连工作站**，这简化了部署：

```
工作站 (Ubuntu)
├── SpaceMouse (HID)  ──┐
├── D405 (USB3)       ──┤
└── Panthera (ttyACM) ──┴─→ 我们的栈
                             ├── 安全层 SafetyLayer
                             ├── RealBackend (200 Hz)
                             └── 策略（BC / RL / CTC）
```

⭐ **好处**：

* 不用交叉编译、不用往板卡传模型
* 训练和推理同一台机器，调试快
* GPU 直接可用（RL 训练 + 视觉推理）

⚠️ **代价**：

* 不能脱机运行（演示时要带电脑）
* USB 那一段的延迟进入控制回路 —— **这正是 commission 第 3 步要测的**

> 📌 待办变更：原计划的"板卡部署"降级为**后期可选项**。
> 客服问题 Q11（板卡算力）从 P1 降到 P3。

## 五、⚠️ SpaceMouse 适配的技术难点

SpaceMouse 输出的是**6 维笛卡尔速度**，LeRobot 要的是**关节位置**。中间要过一次微分 IK：

```
SpaceMouse (6DoF)
  → 死区 + 缩放           ⚠️ 不做死区，手不碰它也会漂
  → 笛卡尔速度 v_des
  → 微分 IK: q̇ = J⁺_λ v   ⚠️ 必须用阻尼伪逆（6轴方阵，奇异点会爆）
  → 积分 q_des += q̇·dt    ⚠️⚠️ 积分漂移见下
  → 夹到关节限位           ⚠️ 不夹的话 SDK 会静默丢弃整条指令
  → LeRobot action
```

### ⚠️⚠️ 积分漂移是最大的坑

$q_{des}$ 靠积分累积，而真机 $q$ 有跟踪误差。两者会**越差越远**：

* 手停下来了，但 $q_{des}$ 已经跑到手臂到不了的地方
* 松手后手臂继续往那个位置冲

⭐ **对策**：$q_{des}$ 与实测 $q$ 的偏差超过阈值时，把 $q_{des}$ **拉回**到
$q + \text{clip}(q_{des}-q)$。这叫"防积分饱和"，和 PID 的 anti-windup 同理。

### 其他必须处理的

| 项 | 对策 |
|---|---|
| 6 轴无冗余、奇异点 | DLS 阻尼伪逆（已有 `_dls_pinv`）|
| 速度超限 | 官方 `velocity_limits: 1.0` |
| 关节限位 | 夹紧（否则 SDK 静默丢弃）|
| 抖动 | 一阶低通 + 死区 |
| 夹爪 | SpaceMouse 两个按键 → 开/合 |

## 六、建议的推进顺序

⚠️ **不要一上来就做 BC。** 顺序是有依赖的：

| 阶段 | 做什么 | 依赖 | 状态 |
|---|---|---|---|
| **0** | 上电调试（commission 7 步） | — | ✅ 脚本已就绪 |
| **1** | 参数辨识（装 D405 **之前**） | 阶段 0 | ✅ 代码就绪 |
| **2** | CTC / 阻抗真机验证 | 阶段 1 | ✅ 代码就绪 |
| **3** | **SpaceMouse 遥操** | 阶段 0 | 🚧 要写 |
| **4** | 装 D405 + 手眼标定 + **再辨识一次** | 阶段 3 | ⭐ 白拿对照数据 |
| **5** | BC 数据采集 + 训练 | 阶段 3,4 | 官方框架 |
| **6** | IsaacLab 环境 + RL 训练 | 阶段 1 | 要写 |
| **7** | BC+RL 组合 + 四象限对照 | 全部 | 最终目标 |

⭐ **阶段 3（SpaceMouse）优先级提前了**：它不只是遥操，还是
**阶段 5 BC 的数据来源**，以及**阶段 2 的人工验证手段**
（手推着走一遍，比看曲线直观）。

⚠️ **阶段 4 的顺序很重要**：D405 装上会改变末端惯量。
装之前辨识一次、装之后再一次，白拿一组"末端负载变化"的对照数据——
这组数据对**域随机化范围**的确定很有价值。
