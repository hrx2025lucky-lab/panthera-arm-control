# Panthera-HT 技术咨询

您好！我们刚入手一台 Panthera-HT，准备用它做机械臂控制与强化学习 sim2real 的研究项目。

在等机器到货的这段时间，我们把官方仓库（`Panthera-HT_SDK`、`Panthera-HT_RoboTwin`、
`Panthera_HT_SDK_Extensions`）都读了一遍，也在 MuJoCo 里搭好了仿真模型。
过程中积累了一些问题，整理如下，麻烦帮忙看看。

**我们的项目计划**分三个阶段：

1. **轨迹跟踪** —— 只用手臂，做参数辨识 + 计算力矩控制（CTC）/ 阻抗 / 自适应控制
2. **状态型抓取** —— 加夹爪，用强化学习训练抓取策略
3. **视觉抓取** —— 加 D405，把视觉接进来

问题按优先级排了序。**如果时间有限，最想知道前 6 条（★ 标记）的答案。**
每条都写了"为什么问"，方便判断我们真正需要的是什么。

## 一、安全相关（上电前最想确认的）

### ★ 1. 三个电机保护默认是关闭的，这是有意为之吗？

在 `robot_param/motor_param/6dof_Panthera_params_follower.yaml` 里看到：

```yaml
motor_timeout_ms: 0        # 注释说明"设为 0 表示禁用超时功能"
pos_limit_enable: false    # 每个电机都是 false
tor_limit_enable: false    # 每个电机都是 false
```

**想请教**：

1. 出厂建议值分别是多少？
2. `motor_timeout_ms` 触发后进入的"阻尼模式"，具体是什么行为？
   阻尼有多大——手臂会缓慢下垂，还是基本能停住？
3. 做力矩控制时，这几项您建议开还是关？

**为什么问**：我们要用 Python 跑力矩闭环。Python 有垃圾回收停顿、被系统抢占的可能。
如果超时保护是关闭的，控制循环一旦卡住，电机会保持上一条力矩指令继续输出——
这是力矩控制里最危险的失效模式。我们已经在软件层写了看门狗，
但如果硬件层能兜底会更放心。

### 2. `tor_upper: 5 / tor_lower: -3` 是占位值吗？

配置里 7 个电机（包括夹爪）的这两个数完全一样，而且不对称。

**想请教**：

1. 这是出厂占位值，还是有实际含义？
2. 单位是**电机端**力矩还是**关节端**（减速后）力矩？
3. 为什么正负不对称（+5 / −3）？
4. J1（关节端堵转 21 N·m）和夹爪用同一个数，是正常的吗？

**为什么问**：想知道启用之后电机自己会不会限力矩。数值含义不清楚，我们不敢开。

### ★ 3. 力矩控制的示例里 `set_stop()` 都是注释掉的，程序退出时手臂会掉下来吗？

我们注意到：

- `2_gravity_compensation_control.py` 等**力矩控制示例**里，
  `except KeyboardInterrupt` 分支的 `robot.set_stop()` 都处于注释状态（共 13 处）
- 而 `1_forward_kinematics_test.py` 这类**位置控制示例**里是启用的
- 同时配置里 `exit_motor_brake_flag: true`，注释写"系统退出时电机自动释放刹车，允许自由运动"

**想请教**：

1. 力矩模式下按 Ctrl+C 或程序崩溃，手臂会直接落下来吗？
2. `set_stop()` 是断使能还是把力矩置零？
   我们在 `Panthera.py` 里没找到它的定义，是在 `hightorque_robot` 预编译包里吗？
3. 关节有抱闸吗？断电瞬间靠什么托住手臂？
4. 有硬件急停接口吗？推荐怎么接？
5. 力矩模式下，您推荐的安全退出流程是什么？

**为什么问**：这是我们上电前要演练的第一件事。

### 4. 底座应该怎么固定？

**想请教**：

1. 官方推荐的固定方式是什么？（桌面夹具 / 螺栓 / 配重底板？）
2. 手臂在最大加速度（配置里是 2.0 rad/s²）下伸直运动时，
   底座承受的倾覆力矩大约多少 N·m？
3. 自重 4.35 kg、臂展 860 mm，只靠自重放在桌面上够吗？还是必须夹紧或打螺栓？
4. 底座安装孔位图有吗？

**为什么问**：我们做参数辨识时要跑"六个关节同时高频运动"的激励轨迹，
比一般演示动作激烈不少。辨识的前提是基座固定，底座一晃数据就全废了，
更担心的是把机器甩坏。

### 5. 力矩控制和强化学习实验的保修边界在哪？

我们要做的操作风险相对高：纯力矩控制、六轴同时高频激励、
强化学习策略部署（训练早期的策略输出可能比较激进）。

**想请教**：

1. 哪些操作会导致保修失效？纯力矩模式在保修范围内吗？
2. 最常见的损坏模式是什么？（减速器 / 电机 / 编码器 / 线束）
3. 有备件卖吗？（单个关节模组、线束、夹爪）价格和周期大概如何？
4. 有没有一份"这样做会损坏机器"的明确清单？

**为什么问**：与其撞坏了再问，不如先知道边界。如果某些操作有风险，
我们愿意在软件层加保护，只是需要先知道是哪些。

## 二、控制接口

### 6. 整臂力矩闭环实际能跑到多少 Hz？一次往返多少毫秒？

我们看到的情况：

- 拓扑上 7 个电机共用一个 `/dev/ttyACM`，波特率 4 Mbps
- 官方示例的控制率跨度很大：
  - `2_gravity_compensation_control.py`：`sleep(0.002)`，500 Hz
  - `2_gravity_friction_compensation_control.py`：`sleep(0.005)`，200 Hz
  - `7_gamepad_cartesian_vel_control.py`：100 Hz，而且用了绝对截止时间调度，
    还有 `max_control_dt = 0.03` 处理超时

**想请教**：

1. `send_get_motor_state_cmd()` + `pos_vel_tqe_kp_kd()` 一个完整往返，实测多少 ms？
2. 整臂闭环力矩控制，实测能稳定跑到多少 Hz？
3. 抖动有多大？最坏情况单个周期能到多少 ms？
4. `7_gamepad` 里的 `max_control_dt = 0.03` 是遇到过实际问题才加的吗？

**为什么问**：我们在仿真里测过控制器对通信延迟的敏感度，发现有个比较陡的拐点：
延迟 4 ms 时跟踪误差正常，6 ms 时误差涨到 15 倍并出现力矩饱和。
知道真实延迟，我们就能直接算出可用的控制带宽，不用上真机试错。

### ★ 7. 力矩控制时，`get_current_pos()` 拿到的是当前状态还是上一周期的？

我们统计了所有示例脚本：

| 示例类别 | 是否调用 `send_get_motor_state_cmd()` |
|---|---|
| 力矩控制（`2_*`、`3_*`、`4_*`） | 一个都没有 |
| 遥操作 / 运动学（`0_*`、`1_*`、`5_*`、`7_*`） | 全部都有 |

而 `0_robot_set_zero.py` 里的注释写着"利用运控模式发送控制帧以读取电机反馈状态"。

**想请教**：

1. `pos_vel_tqe_kp_kd()` 内部的 `motor_send_cmd()` 会顺带触发状态回传吗？
2. 如果会，那下一次 `get_current_pos()` 读到的是这一帧指令之后的状态，
   相当于反馈里天然有一个控制周期的延迟——这个理解对吗？
3. 力矩控制循环里到底要不要显式调用 `send_get_motor_state_cmd()`？
   调用了会不会变成每周期两次往返，把控制率砍半？
4. 有没有"发指令的同时拿回状态"的单次往返接口？

**为什么问**：这关系到闭环反馈的正确性。如果力矩环用的是上一周期的状态，
就等于凭空多了一拍延迟。结合上一条提到的延迟拐点，一拍可能就是决定性的。

### 8. `get_current_torque()` 读到的力矩是怎么来的？精度如何？

**想请教**：

1. 是电流估算（力矩常数 × 电流 × 减速比）还是有力矩传感器？
2. 出厂标定过吗？标称精度或线性度是多少？
3. 有温漂吗？连续运行 30 分钟大概会漂多少？
4. 摩擦和减速器效率算在里面了吗？

**为什么问**：参数辨识的输入就是这个力矩，所以它的精度直接决定辨识做不做得成。
我们在仿真里验证过：测量噪声 0.02 N·m 时参数误差约 0.7%；
但如果实际噪声大一个量级或者有系统性偏置，整套辨识方案就要重新设计。

### 9. 力矩限幅应该用哪一套？

官方示例里出现了三套不同的值：

| 值 | 出现次数 |
|---|---|
| `[10, 20, 20, 10, 5, 5]` | 2 处 |
| `[15, 30, 30, 15, 5, 5]` | 8 处 |
| `[21, 36, 36, 21, 10, 10]` | 2 处，与 `Follower.yaml` 的 `max_torque` 一致 |

**想请教**：

1. 这三套分别是什么含义？（额定 / 峰值 / 堵转 / 短时允许？）
2. **连续运行**（比如跑 10 分钟辨识轨迹）安全的持续力矩是多少？
3. 峰值力矩允许持续多久？有热保护吗？触发后是什么表现？

**为什么问**：我们目前保守取了最小的一套。但如果那其实是"额定"值，
我们就白白浪费了一半控制权限；反过来如果连续运行的限值更低，
我们的辨识轨迹可能会烧电机。

## 三、强化学习与 sim2real（我们项目的主线）

我们的计划是：**IsaacLab 训练 → MuJoCo 做 sim2sim 交叉验证 → 真机部署**。

### 10. 官方或社区有做过强化学习吗？

我们看到 `Panthera-HT_RoboTwin` 是基于 RoboTwin 2.0 + SAPIEN，
面向 ACT / Pi0 / RDT / DP 等**模仿学习**方案，
README 里也写明"不包含真机 SDK、真机控制或 sim-to-real 安全保证"。

**想请教**：

1. 有没有**强化学习**（PPO / SAC 这类）方向的官方或社区工作？
2. 有 IsaacLab / Isaac Gym / MuJoCo 的官方环境吗？还是目前只有 SAPIEN？
3. 有 USD 格式的模型吗？还是需要我们自己从 URDF 转？
4. RoboTwin 采集的专家数据训出来的策略，有成功部署到真机的案例吗？
   成功率大概什么水平？
5. `Panthera_digital_twin` 用的是什么物理引擎？和 RoboTwin 是什么关系？

**为什么问**：如果官方还没做过 sim2real，那我们要自己承担全部风险，
也就更依赖前面那些底层参数（延迟、力矩精度、转子惯量）。这直接影响我们的时间预算。

### 11. 强化学习策略部署，推荐跑在上位机还是板卡？

**想请教**：

1. 策略是一个 ONNX 模型（2~3 层 MLP，50~100 Hz），推荐跑在板卡还是上位机？
2. 如果跑板卡，板卡上能直接调用 `hightorque_robot` 吗？
   （`motor_whl/` 里有 aarch64 的 wheel，是给板卡用的吗？板卡跑什么系统？）
3. 如果跑上位机，USB 那一段的延迟和抖动会不会成为瓶颈？
4. 有人做过脱机运行吗（不接电脑，上电即跑）？

### ★ 12. 强化学习策略用 MIT 模式时，kp/kd 应该取多少？

强化学习的标准做法是策略**输出关节位置目标**，由电机内部的 PD 执行：

```
τ = kp × (q_des − q) + kd × (q̇_des − q̇) + τ_ff
```

**想请教**：

1. `pos_vel_tqe_kp_kd()` 里 kp / kd 的**单位**是什么？
   （N·m/rad 和 N·m·s/rad？还是电机内部的无量纲标度？）
2. kp / kd 的取值范围是多少？超过多少会不稳定？
3. 各关节推荐的 kp / kd 是多少？
4. 电机内部的 PD 是纯 PD，还是带积分 / 前馈 / 滤波？有没有内部限幅？

**为什么问**：这是整个部署链路里最关键的一组数。
训练时仿真里的 PD 增益必须和真机电机内部的 PD 完全对齐，否则策略学到的是另一台机器。
单位不明确的话就无法对齐。

### 13. 零位可重复性：断电重启后还是同一个零位吗？

**想请教**：

1. 编码器是单圈还是多圈？断电后位置记忆保持吗？
2. `0_robot_set_zero.py` 设的零位是写进电机 flash，还是只在本次会话有效？
3. 断电重启后，同一个物理姿态读出来的关节角，重复性是多少？（±多少 rad）
4. 有机械式的零位标定工装或限位块吗？

**为什么问**：零位漂移对 sim2real 影响很大但很隐蔽。
策略是在"关节角等于某个数"的世界里训练的，如果真机今天的零位和昨天差 0.05 rad，
策略看到的观测就整体偏移了，表现会莫名其妙变差，而且很难排查——因为看起来一切正常。
知道重复性，我们才能决定是每次开机重新标定，还是把它当成域随机化的一项。

### 14. 域随机化应该随机化哪些参数，范围多大？

我们注意到官方仿真资产里没有动力学参数：

- `RoboTwin/assets/embodiments/panthera-6dof/panthera_6dof.urdf`
  里 `<dynamics>` 标签数量为 0（没有 damping、没有 friction）
- 其 link2 惯量 `izz="0.02272105"` 与 SDK 版 URDF 完全一致
  ——看起来两边用的都是同一份 CAD 惯量

**想请教**（这些是我们定随机化范围的依据）：

1. **个体差异**：同型号不同机器之间，摩擦、力矩常数、背隙的离散度大概多少？
2. **温漂**：连续运行 30 分钟后，摩擦和力矩输出会变化多少？
3. **磨合**：新机器和跑过 100 小时的机器，摩擦差多少？
4. **负载**：装上夹爪（以及后续的相机）后，末端的质量和惯量参数你们有数据吗？

**为什么问**：域随机化的关键是范围要覆盖真机但又不能太宽——
太窄会 sim2real 失败，太宽会让策略过度保守、性能下降。
这些离散度数据是定范围的主要依据。

### 15. 强化学习策略的输出可能比较"抖"，硬件层有什么保护？

**想请教**：

1. 电机固件里有指令变化率限制（力矩斜率 / jerk 限制）吗？
2. 连续下发相邻两帧差异很大的位置目标，电机会怎么反应？
3. 有推荐的"策略输出 → 电机指令"之间的滤波或限幅做法吗？
4. 长时间高力矩运行时，过热保护什么时候触发？触发后是降额还是直接断使能？

### 16. 观测量能拿到哪些？各自的延迟是多少？

强化学习的观测通常是 `[q, q̇, τ, 上一帧动作, ...]`。

**想请教**：

1. `get_current_pos` / `vel` / `torque` 三个量的时间戳是同一时刻的吗？
2. 速度是直接测量的，还是由位置差分得到的？如果是差分，用了什么滤波？
3. 有 IMU 或其他额外传感器可用吗？
4. 夹爪的位置和力反馈能读吗？延迟和关节一样吗？

**为什么问**：观测的延迟和滤波特性必须在仿真里复现，
否则策略在真机上看到的观测和训练时不是一回事。
"速度是不是差分出来的"尤其重要——差分速度的噪声和相位特性和真实速度差别很大。

## 四、夹爪（我们的第二阶段要用）

从 SDK 里看到的接口：

```python
gripper_control(pos, vel, max_tqu=0.5)          # 默认最大力矩 0.5 N·m
gripper_control_MIT(pos, vel, tqe, kp, kd)      # 支持 MIT 五参数模式
gripper_open(pos=1.6)  /  gripper_close(pos=0.0)
```

配置里 `gripper_limits: 0.0 ~ 2.0`，电机型号 `3536_32`。

### 17. 夹爪的力学指标是多少？

1. 最大夹持力是多少牛？`max_tqu = 0.5` N·m 对应指尖多大的力？
2. 行程 0~2.0 的单位是什么（rad？），对应指间开口多少 mm？
3. 是平行夹爪还是连杆式？指尖轨迹是直线还是弧线？
4. 夹爪加法兰装上之后，末端增加的质量和惯量是多少？
   （我们要加进动力学模型，否则 J5 / J6 的辨识和控制都会偏）

### ★ 18. 夹爪能做力控吗？力反馈准不准？

1. `gripper_control_MIT` 的 `tqe` 能做恒力夹持吗？还是只能当限幅用？
2. `get_current_torque_gripper()` 读到的力矩，能换算成指尖夹持力吗？换算系数是多少？
3. 这个力反馈标定过吗？精度大概多少？
4. 抓易碎物体（比如纸杯）时，您推荐怎么控？

**为什么问**：强化学习的奖励函数要判断"抓稳了没有"。
如果只能靠位置判断（夹爪合到某个开度就算抓住），
容易训练出"夹住空气也拿奖励"的策略。有力反馈才能写出正确的奖励。

### 19. 夹爪的响应速度和重复性？

1. 从全开到全闭需要多长时间？
2. 夹爪指令的延迟和关节一样吗？
   （我们的策略在 50~100 Hz 输出，夹爪那一维如果慢很多，训练时要单独建模）
3. 重复定位精度是多少？
4. 长时间保持夹持力会发热或降额吗？

### 20. 指尖可以更换吗？

1. 指尖是可拆换的吗？有官方的软性 / 防滑指尖吗？
2. 指尖材质的摩擦系数大概多少？
3. 如果自己 3D 打印指尖，接口尺寸图有吗？

**为什么问**：抓取成功率对指尖摩擦很敏感，而这也是 sim2real 里最难对齐的一项。
知道真实材质才好定随机化范围。

## 五、视觉（我们的第三阶段，D405 还没买）

我们看到 `Panthera_HT_SDK_Extensions` 已经有比较完整的视觉方案：
**D405 Eye-in-Hand + 手眼标定 + YOLO 检测 + PBVS 视觉伺服 + GraspNet 抓取规划**，
标定板用 8×8 棋盘格（内角点 7×7、方格 20 mm）。

这是一条传统视觉管线（检测 → 位姿 → 抓取规划 → 执行）。
我们计划做的是"强化学习策略 + 视觉观测"，路线不太一样，所以想先确认几件事。

### 21. 相机怎么安装？有官方支架吗？

1. D405 装在哪个位置？有官方支架吗（3D 打印件或金属件）？能提供模型文件吗？
2. 装上相机后，末端增加的质量和惯量是多少？
3. 相机和夹爪能同时装吗？会互相遮挡吗？夹爪闭合时指尖在相机视野里占多大？
4. D405 最近工作距离约 7 cm，Eye-in-Hand 装法在抓取的最后阶段，
   物体会不会近到看不见？你们实际是怎么处理的？
5. 线缆怎么走？关节转到极限位置时会不会被拉扯或缠绕？

### 22. 手眼标定的精度和稳定性如何？

1. `9_hand_eye_calibration.py` 标定出的 `T_tcp_camera`，典型精度是多少？（mm / 度）
2. 标定结果能保持多久？拆装相机后必须重标吗？磕碰一下呢？
3. 标定精度受关节零位影响吗？（如果零位漂了，标定还有效吗——和第 13 条相关）
4. 推荐采集多少个姿态？有没有判断"标定质量好不好"的指标？

**为什么问**：手眼标定误差会直接变成抓取位置误差，而且会和关节零位漂移叠加。
我们需要知道这个误差的量级，才能决定第二阶段训练时给物体位姿注入多大噪声——
注小了到第三阶段会失效，注大了策略又会过度保守。

### 23. 有 D405 的仿真渲染参数吗？

1. 有 D405 在仿真里的相机参数吗？（内参、FOV、分辨率、深度噪声模型）
2. RoboTwin 里的"头部相机 / 腕部相机"用的是什么参数？和真实 D405 对得上吗？
3. D405 的深度噪声特性有实测数据吗？（不同距离下的标准差）
4. 有人做过"仿真渲染 vs 真实图像"的差距评估吗？

**为什么问**：第三阶段的 sim2real 里，渲染差距是一项全新的误差来源
（第一阶段只有动力学差距，第二阶段加了接触差距）。
如果仿真相机参数和真机对不上，策略在仿真里看到的世界和真机完全不同。
深度噪声尤其重要——D405 在近距离、反光、透明物体上表现差异很大，
这些必须在仿真里建模。

### 24. 官方的 GraspNet 方案实际效果如何？

1. `Panthera-HT_graspnet` 的鸭子抓取 demo，实际成功率大概多少？
2. 对没见过的物体泛化如何？换个形状还能用吗？
3. 整条管线（检测 → 位姿 → 规划 → 执行）跑一次要多久？
4. 最常见的失败模式是什么？（检测失败 / 位姿不准 / 抓取点不好 / 夹爪打滑）

**为什么问**：这套方案是我们的对照基线。
我们要说明"强化学习 + 视觉"有没有价值，就得和它比。
知道它的成功率和失败模式，我们才知道该往哪个方向做。
如果它已经很好用了，我们的切入点就要换个角度（比如速度、鲁棒性、或者不依赖 CAD 模型）。

### 25. 视觉伺服跑多少 Hz？延迟多大？

1. D405 出图到能用于控制，端到端延迟大概多少 ms？
2. 视觉伺服循环实际跑多少 Hz？
3. 视觉这一路和高频的力矩控制怎么配合？（分线程？分频？）

**为什么问**：我们的架构里视觉是低频（约 30 Hz）、控制是高频（200~500 Hz）。
两者怎么解耦、视觉延迟怎么补偿，是第三阶段的核心工程问题。

## 六、模型参数（做参数辨识用）

### ★ 26. URDF 里的 `<inertia>` 包含转子惯量吗？

1. URDF 里的惯量是纯 CAD 几何导出的，还是含了电机转子的反射惯量？
2. 能提供转子惯量 $J_m$ 吗？（按型号：5047 / 6056 / 4438）

**为什么问**：减速比 36 意味着反射惯量是 $J_m \times 36^2$。
按典型值 $J_m \approx 10^{-5}$ 估算约 0.013 kg·m²，
而 URDF 里 link2 的 $I_{zz}$ 只有 0.0227——反射惯量占了约 57%。
这个量级 CAD 是导不出来的。如果 URDF 里没有包含，
我们的仿真模型就会系统性偏小一半，sim2real 差距会很大。
这可能是影响仿真保真度最大的一个数。

### 27. 示例里的摩擦系数是辨识值还是经验值？

`2_gravity_friction_compensation_control.py` 里给了：

```python
Fc = [0.20, 0.15, 0.15, 0.15, 0.04, 0.04]   # 库伦摩擦
Fv = [0.06, 0.06, 0.06, 0.03, 0.02, 0.02]   # 粘性摩擦
```

注释写着"需要根据实际机器人进行辨识和调整"。

1. 这组数是某台样机的实测值，还是经验估计值？
2. 不同个体之间差异有多大？
3. 出厂有逐台标定数据随机器附带吗？
4. 有官方推荐的辨识流程或脚本吗？

### 28. 能读电机温度吗？能单独使能 / 去使能某个关节吗？

我们在 `Panthera.py` 里没有找到这两个接口。

1. 有读电机温度的接口吗？（在 `hightorque_robot` 预编译包里吗？）
2. 能单独去使能某一个关节，让它自由转动而其他关节保持不动吗？
3. 电机温度到多少会触发降额或保护？触发后是什么表现？

**为什么问**：这两条都影响我们的辨识方案。

- **温度**：摩擦系数强烈依赖温度。我们的激励轨迹要连续跑 10 分钟以上，
  期间如果摩擦漂移了，辨识出来的就是一个"平均意义上谁也不是"的值。
  能读温度的话我们可以把它作为协变量记录下来；读不到就只能靠"每次先热机若干分钟"，
  而且没法验证这个做法到底有没有用。
- **单独使能**：辨识的常见做法是固定其他关节、单独激励一个关节，能明显改善数值条件。

### 29. 能提供电机的电气参数吗？

力矩常数 $k_t$、相电阻 $R$、减速器效率、背隙（arcmin）。

**为什么问**：$k_t$ 和 $R$ 用于前馈补偿和能耗分析；
效率影响"指令力矩 → 实际输出力矩"的换算；
背隙决定位置精度上限，也是域随机化要考虑的一项。
