## 三、⚠️⚠️ 三条必须记住的规矩

### ① 模型里有占位参数

官方 URDF 是 **CAD 导出**的，连杆几何/惯量可信，但缺三样：

| 缺什么 | 现状 |
|---|---|
| 执行器 | ✅ 转换脚本已补（原始 URDF `nu=0`） |
| **转子反射惯量** `armature` | ⚠️ **占位**（`ROTOR_INERTIA_GUESS = 1e-5`） |
| **关节摩擦** | ⚠️ **占位**（取自 SDK 注释的「建议初始值」） |

**为什么不能忽略转子惯量**：$J_{rotor}\times N^2 = 10^{-5}\times36^2 = 0.013$，
而 link2 的 $I_{zz}$ 只有 **0.0227** —— **57%，同一量级**。

⭐ 变量名带 `_GUESS` 后缀就是提醒「还没辨识」。**辨识回填后才去掉后缀。**

### ② 力矩限幅永远不许放开

armctrl 的 `_convert_to_torque_actuators()` 会把 `ctrlrange` 设成 ±1e6
（纯仿真无所谓）。**本项目刻意删掉了那两行**，因为代码要原样下发真机。

限幅值 `[10, 20, 20, 10, 5, 5]` N·m 取自官方 SDK 示例。
`test_model.py::test_torque_limits_are_not_disabled` 专门守这一条。

> ⚠️ 力矩上限有**三个来源**别混：URDF `effort`＝堵转（21/36/…）、
> 参数手册额定（6/10/…）、SDK 示例限幅（10/20/…）。本项目取最后一个。

### ③ 6 轴没有零空间

6 关节对 6 维任务空间**零冗余**，零空间投影矩阵的秩恒为 **0**（Panda 是 1）。

`impedance.py` 里保留了零空间项，但它**恒返回零向量**。保留仅为与 armctrl
逐行对照。⭐ **不要因为「跑通了」就认为零空间在起作用**——
`test_no_redundancy` 会断言它确实退化。

## 五、⭐ sim2real 的流程与判据（最重要的一节）

### 流程（标准三段，别改）

```
辨识参数 ──→ 同步进 IsaacLab(USD) 与 MuJoCo(MJCF)
                  │                    │
            训练(PPO, 数千并行)          │
                  │                    │
               策略 ──── sim2sim 验证 ──┘   ← ⭐ 独立引擎交叉检验
                  │
                真机部署
```

⭐ **中间那步为什么重要**：IsaacLab 用 PhysX、MuJoCo 用自己的求解器，
是**两套独立实现**。策略在 A 能跑、到 B 就废 ⇒ 它过拟合了 A 的数值特性。
这是「判据必须独立」在仿真环节的应用。

⚠️ **但这个判据有前提：两边模型必须一致。**
`armature` 最容易在 URDF→USD 转换里悄悄丢掉。丢了以后 sim2sim 对不上，
你会以为是「引擎差异」，实际是「模型没对齐」——两种原因混在一起，判据就脏了。

⇒ 所以有 `tests/test_model_parity.py`，导出**物理指纹**（质量/armature/
摩擦/限幅/减速比），在 Isaac 侧也导一遍逐项 diff。

### 判据设计的铁律

> **判据不能来自被测对象自己。**

| ❌ 不能用 | 为什么 |
|---|---|
| 「补偿后力矩残差变小」 | 残差由补偿器自己算，自证循环 |
| 「仿真里跑得更像了」 | 仿真模型正是被改动的对象 |
| 真机 `get_current_torque()` 自证控制器 | 它是**电流×固定系数**估算，属「自报」档 |

| ✅ 可以用 | 为什么独立 |
|---|---|
| ⭐ 同一条力矩序列**开环下发**，比末端实际轨迹 | 不涉及任何反馈或补偿 |
| **留出验证轨迹**：A 组辨识、B 组评估 | B 组没参与拟合 |
| 阶跃响应的上升时间/超调 | 时域特征，与参数化形式无关 |

⚠️ **一个具体的陷阱**：SDK 有 `get_friction_compensation()`。
**不要**把同一组 $F_c,F_v$ 既用于控制器补偿、又填进仿真当摩擦——
那样 sim 和 real 会「看起来很对」，因为两边用的是同一组假数。
（armctrl 批次 E-2 的同类陷阱：补偿端和被控对象端共用同一个量。）

## 五之二、⭐ 最终目标：辨识 vs 域随机化的对照实验

本项目的终点不是「把算法搬上真机」，而是一个对照实验：

|  | CAD 模型 | 辨识后模型 |
|---|---|---|
| 传统控制（CTC / 阻抗） | A | B |
| RL + 域随机化 | C | D |

⭐ **核心论点**：「RL 不需要精确模型」只对了一半——
不需要精确的**点估计**，但需要合理的**分布**。辨识给的正是分布的中心和 σ。
不辨识 ⇒ 随机化范围只能拍宽 ⇒ 策略保守、性能下降。

还有一条**随机化宽度扫描曲线**（±0σ → ±1σ → ±3σ → 拍脑袋宽范围），
预期是倒 U 形；最优点比"拍脑袋"好多少，就是辨识值多少钱。

⚠️ 方法论前提：控制变量、评估轨迹不得参与辨识/训练、
RL 至少 3~5 个种子报均值方差、判据必须独立（开环对照而非闭环跟踪误差）。

**⚠️ 前提：统一控制目标**（`辨识与域随机化对照实验.md` §一之二）
四格必须跑**同一条参考轨迹**、比**同一个主指标**（TCP 轨迹 RMS 误差，外部可观测）、
**信息对等**（RL 的 obs 要含参考轨迹未来 N 步，因为 CTC 知道完整轨迹）。
⚠️ 唯一不能强行统一的是**动作空间**（CTC 出力矩、RL 出位置目标）——
各用各的标准接口，差异写进结论。

**任务分三阶段**（`RL_sim2real流程.md` §二）：

| 阶段 | 任务 | 硬件 | gap 来源 |
|---|---|---|---|
| **1** | ⭐ 轨迹跟踪（四象限用这个） | 只要臂 | **仅动力学** |
| 2 | 状态型抓取（物体位姿直接给） | ＋夹爪 | ＋接触 |
| 3 | 视觉抓取 | ＋D405 | ＋渲染＋位姿估计 |

⭐ **四象限对照必须用阶段 1**：抓取的 gap 混着四项，分不清改善来自哪一项。

⭐ **视觉走「解耦」方案**（§2.3）：D405 → 位姿估计模块 → 物体位姿 → 策略。
视觉模块单独开发、单独验证，**不进 RL**。这样阶段 2 训好的策略能直接复用，
仿真里完全不用渲染，两个模块还能分别测误差。
⚠️ 但阶段 2 训练时就要给物体位姿**注入噪声**（幅度取视觉实测误差），否则到阶段 3 会崩。

⇒ **D405 推迟到阶段 3 再买**（那时也更清楚需要多高精度）。

⭐ **轨迹速度是实验设计的一部分**：太慢则四格结果全一样。
选定后必须做「前提检查」——CAD 模型 vs 辨识模型跑同一条轨迹，
差异明显才算合格。推荐圆、半径 0.10 m、周期 2.5 s。

完整设计见 `docs/辨识与域随机化对照实验.md`，
八步流程与部署架构见 `docs/RL_sim2real流程.md`。

## 六、下一步该做什么

### 优先级 1：调参台（4 个场景，不是 12 个）

armctrl 的调参台 9114 行，全套移植没必要。只要这四个：

| 场景 | 为什么 |
|---|---|
| `impedance` | 拖 K 看 $F/K$——真机第一个能立刻对照的判据 |
| `gravity` | 重力补偿开/关，手推感受 |
| `identify` | ⭐ **激励轨迹可视化 + 条件数实时显示**（armctrl 没有，是新的） |
| `tracking` | PD vs 计算力矩，辨识前后对照 |

⭐ **关键**：调参台要能**同时挂仿真和真机两个后端**，读数并排。
接口已经有了（`driver/backend.py`），这是它在本项目里的核心价值。

### 优先级 2：算法迁移

全库只有 **3 处硬编码 7**（`ilc.py` ×2、`planning/scene.py` 的 `N_ARM`），
其余维度无关。**代码几乎免费，成本在真机重测数字**。

建议顺序（按依赖，不按篇号）：
```
identification → ctc/adaptive → momentum_observer → planning/ilc → servo
```
⭐ **先辨识**：CTC 和自适应都依赖模型，用 CAD 假参数上 CTC 会花好几天
调一个「模型本来就不对」的控制器。

### 优先级 3：真机上电（臂到货后）

⛔ **这四件事做完之前不要跑整臂力矩控制**：
1. **实测控制频率**（官方示例 `sleep(0.002)` 是期望值不是实测值）
2. **单关节先行**，从 `tau=0` 开始加，手放急停旁
3. **看门狗**：循环卡住自动置零力矩
4. **验证限幅生效**：故意下发超限力矩，确认被截断

## 八、协作方式

* **判据独立**：任何「变好了」的结论，都要问「这个判据除了我关心的原因，
  还有别的原因能让它变化吗？」
* **数字要标档位**：`实测` / `理论`（独立解析算出）/ `真值` / `自报`
* **占位值必须显式标记**，别让它悄悄变成结论
* 讲义在 `armctrl_讲解/`（私有，不随公开仓分发），
  **15 篇是控制地基、14 篇是机器人学地基**，需要补概念时看那两篇
