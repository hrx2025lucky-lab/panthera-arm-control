> 目的：确认我们做的东西**和官方资料是否匹配**，不匹配的地方是**有意的**还是**错的**。
>

> `Panthera-HT_SDK`、`Panthera-HT_ROS2`、`Panthera-HT_RoboTwin`、
> `Panthera_HT_SDK_Extensions`

> 结论先说：**技术栈方向一致，5 处不匹配已处理，2 处有意保留差异。**

## 二、🔴 已修正的不匹配

### 2.1 阻抗刚度高了一个数量级（最严重）

| | 位置刚度 (N/m) | 姿态刚度 (N·m/rad) |
|---|---|---|
| 我们（从 Panda 沿用） | 400 | **30** |
| **官方 Panthera** | **140** | **1.4 / 1.4 / 0.9** |
| 倍数 | 2.9× | **21~33×** |

⚠️⚠️ 官方源码里的注释道出了原因：

> 「姿态通道保持保守，**避免再次激励 5/6 号腕部电机抖动**」

⭐ **"再次"两个字说明他们踩过这个坑。**
30 N·m/rad 拿到真机上大概率直接激起腕部振荡。

**已改**：`ImpedanceGains` 默认值改为 `k_trans=140`、`k_rot=1.2`，
并把官方注释的原因写进 docstring。

> 教训：**从 armctrl（Panda）沿用过来的每一个数字都要重新验证**。
> 机械臂换了，Panda 是 7 轴、腕部电机大得多。

### 2.2 腕部力矩限幅偏高

| 关节 | 我们 | 官方 ROS2 阻抗示例 |
|---|---|---|
| J1–J4 | 10 / 20 / 20 / 10 | 相同 |
| **J5** | 5 | **3**（低 1.67×） |
| **J6** | 5 | **2**（低 2.5×） |

官方源码注释：「5/6 号腕部电机限幅更低，**减少姿态通道激励**」。

**已加**：`excitation.ROS2_IMPEDANCE_TAU_MAX = [10,20,20,10,3,2]`，
并注明**做力矩控制（尤其阻抗/柔顺）时应该用这一套**。

### 2.3 力矩限幅有四套值（不是三套）

之前统计 Python 示例发现三套，加上 ROS2 是**四套**：

| 值 | 出处 | 含义（推测） |
|---|---|---|
| `[10,20,20,10,5,5]` | SDK Python，2 处 | 最保守 |
| `[10,20,20,10,3,2]` | **ROS2 阻抗示例** | ⭐ 力矩控制专用 |
| `[15,30,30,15,5,5]` | SDK Python，8 处 | ？ |
| `[21,36,36,21,10,10]` | `Follower.yaml` 的 `max_torque` | 堵转扭矩 |

⚠️ 这进一步说明客服问题 **Q9（力矩限幅用哪套）必须问清楚**。

## 三、🟡 有意保留的差异（不是错，但要写清楚）

### 3.1 关节下限：我们用了更严的 Leader 值

| 配置 | J2/J3 下限 |
|---|---|
| **Follower（我们的机器）** | **−0.1** |
| Leader | 0.0 |
| **我们的 MJCF** | 0.0（= Leader） |

⭐ **更严格是安全的**，但辨识时会白白损失 0.1 rad 的工作空间。

**决定**：暂时保留（安全优先）。真机到货实测过零位后再放开到 −0.1。
⚠️ 但要记住：**官方默认配置是 `Follower.yaml`**（ROS2 README 明确写了），
所以真机的可动范围比我们模型宽一点。

### 3.2 摩擦补偿：阈值法 vs tanh 平滑

| | 做法 | 特点 |
|---|---|---|
| 官方 | 速度阈值（`vel_threshold=0.02`），低于阈值不加库伦项 | 阈值处**不连续** |
| 我们 | `tanh(qd/scale)` 平滑 | 连续可导 |

⭐ 我们的做法在数学上更好（连续 ⇒ 不会 chattering），
但做**对照实验**时必须知道这个差异——
否则会把"模型不一样"误判成"辨识结果不对"。

已在 `fake_sdk.get_friction_compensation()` 里复刻官方写法并写了守护测试。

| **强化学习** | ❌ 只有模仿学习（RoboTwin/SAPIEN） | 🚧 计划中 |

所以底层参数（客服问题清单）尤其重要。

### ⚠️ 需要调整的任务

1. **延迟-带宽表**：官方阻抗示例跑 **200 Hz** 而不是我们假设的 500 Hz。
   ⇒ 扫描范围要以 200 Hz 为中心，且 **200 Hz 下的可用带宽是首要结论**。
2. **上电脚本**：应该先照着官方 `1_PD_control` → `2_joint_impedance` →
   `3_cartesian_impedance` 的顺序验证，**跑通官方示例再上我们的控制器**。
   这样出问题能立刻分清是"机器问题"还是"我们代码问题"。
